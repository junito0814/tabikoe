# 読み込み中の見せ方（loading-feedback）

> 出典: [requirement.md](../../requirement.md) 4.5.11・8 章 85〜88、[request.md](../../request.md)「v2 改訂 18（2026-09-30）」

## ユーザーストーリー

利用者として、**押したことが伝わり、待っていることが分かる**ようにしてほしい。なぜなら、いま多くの場面でボタンが押せなくなるだけなので、押せていないのか処理中なのか区別が付かず、連打したり壊れていると思ったりするから。

## この文書の範囲

**利用者が触れる画面だけ**を扱う。管理画面（SC-15〜18・SC-24〜27・SC-32）は **2026-09-30 に保留**とした（要件 4.5.11・9 章 未決定事項 No.14）。管理画面を触るのは管理者だけで、待ち表示が無くても運用できるため、提出（2026-10-07）までの時間を利用者側に充てる。

## 調べて分かったこと（2026-09-30）

### 既にできていること

- 骨組みの部品は `src/components/skeleton/Skeletons.tsx` に 8 種類そろっている
- `loading.tsx` は主要な動線 10 ルートに入っている（検索結果・スポット別・投稿詳細・しおり詳細と一覧・アルバム詳細と一覧・マイページ・通知・行きたい）
- 投稿する・削除する・通報する・ブロックする・コメントする・招待を受ける・二段階確認は、文言が変わる待ち表示が入っている
- 地図のスクリプト読み込み、現在地の取得、写真一覧と通知の追加読み込みも同じく入っている
- **最初の HTML に画面の中身が入っている**（本番で確認）。真っ白のまま待つ状態にはなっていない

### 足りていないこと

| # | 場所 | 症状 |
|---|---|---|
| 1 | しおり詳細 | 待ち状態の変数が 1 つも無い。スポットを外す・Day を移す・名前を変える・しおりを消すは、API と再取得の 2 往復が終わるまで完全に無反応 |
| 2 | あしあとの地図 | 読み込み中に「この範囲に表示できるスポットはありません」と**事実と違う案内**が出る |
| 3 | 保存シート | 楽観更新が無く、チェックがレスポンス後にしか入らない |
| 4 | 招待のユーザー名検索 | 検索中に「見つかりませんでした」と**事実と違う案内**が出る |
| 5 | 投稿画面の「下書きに保存」 | 文言が変わらない。写真・動画のアップロードを含むため最も長い |
| 6 | 投稿画面の既存写真の削除 | 押しても何も起きない（状態も `disabled` も無い） |
| 7 | 投稿一覧・スポット一覧・マイページの投稿 | 絞り込み・並び替え・旅行の切替で**古い一覧がそのまま残る**（待ち表示が「もっと見る」にしか効いていない） |
| 8 | ホーム画面から開いたとき | ウェブアプリのマニフェストも `theme-color` も無く、起動直後に白い一瞬が出る |

### 今回はやらないこと（把握したうえで残す）

- 管理画面の待ち表示 13 か所と、`/admin` 配下 6 画面の `loading.tsx`（9 章 未決定事項 No.14）
- しおりのダイアログ（期間・メンバー・招待リンク）とアルバムの各操作。押せなくなるので二重送信は起きず、見た目だけの問題
- 入力補助の候補取得（スポット名・行き先・アルバム名）。候補が遅れて出るだけ
- **「見えているのに押せない」時間**（最初の HTML が出てから JavaScript が効くまで）。本番の実測で JavaScript は 9 本・248 KB（圧縮後）だが、うち 218 KB は React と Next の土台で減らす余地が無い。押せないように見せると見た目が悪くなるだけなので、何もしない
- 関所（`src/proxy.ts`）の問い合わせを減らすこと。性能改善の Task 3（保留）の範囲

## 受入条件

- [ ] ホーム画面に置いたアイコンから開いたとき、起動直後の下地が白ではなく空の青（`#2F7FD8`）になり、ブラウザの帯の色が画面の地の色と揃っていること（要件 8 章 85）
- [ ] 待っている間に「〜がありません」「見つかりませんでした」が出ないこと。あしあとの地図と招待のユーザー名検索で確かめる（要件 8 章 86）
- [ ] しおり詳細の 4 操作、投稿画面の下書き保存と写真削除、保存シートのチェックで、押した直後に画面が変わること。「押せなくなるだけ」で止まらないこと（要件 8 章 87）
- [ ] 投稿一覧・スポット一覧・マイページの投稿で条件を変えたとき、古い一覧が残らず骨組みに差し替わること（要件 8 章 88）
- [ ] 取り消せる操作（いいね・行きたい・チェック）は押した瞬間に見た目が変わり、失敗したときだけ戻ること
- [ ] 取り消せない操作（削除・投稿）は結果が返ってから画面が変わること
