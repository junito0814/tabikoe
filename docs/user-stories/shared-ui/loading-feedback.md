# 読み込み中の見せ方（loading-feedback）

> 出典: [requirement.md](../../requirement.md) 4.5.11・8 章 85〜88、[request.md](../../request.md)「v2 改訂 18（2026-09-30）」

## ユーザーストーリー

利用者として、**押したことが伝わり、待っていることが分かる**ようにしてほしい。なぜなら、いま多くの場面でボタンが押せなくなるだけなので、押せていないのか処理中なのか区別が付かず、連打したり壊れていると思ったりするから。

## この文書の範囲

**利用者が触れる画面だけ**を扱う。管理画面（SC-15〜18・SC-24〜27・SC-32）は **2026-09-30 に保留**とした（要件 4.5.11・9 章 未決定事項 No.14）。管理画面を触るのは管理者だけで、待ち表示が無くても運用できるため、提出（2026-10-07）までの時間を利用者側に充てる。

## 調べて分かったこと（2026-09-30）

- 骨組みの部品は `src/components/skeleton/Skeletons.tsx` に 8 種類そろっている

- 投稿する・削除する・通報する・ブロックする・コメントする・招待を受ける・二段階確認は、文言が変わる待ち表示が入っている
- 地図のスクリプト読み込み、現在地の取得、写真一覧と通知の追加読み込みも同じく入っている
- **最初の HTML に画面の中身が入っている**（本番で確認）。真っ白のまま待つ状態にはなっていない

### 残っていること（2026-09-30 に範囲を広げた。Task 4〜6）

当初は提出までの時間を考えて「主要な動線」に絞ったが、**UX をよくしたいという方針**を受けて、**利用者が触れる箇所は全部**を範囲に戻した。

**押したとき（Task 4）**

| 場所 | 症状 |
|---|---|
| スポット候補を押したときの登録 | `disabled` も表示も無い。**続けて押すと同じスポットが二重に登録されうる** |
| 近くのコエの移動手段の切替 | 前の結果を消さないので、古いカードと古い分数が残る |
| ホームの行き先の自由入力 | 入力欄を押せなくするだけ。地名の座標化を待つので体感が長い |
| 地図のピン取得・しおりの地図表示 | 無言で遅れて出る。空の地図が「投稿ゼロ」に見える |
| 投稿画面のスポット照合（地図を動かしたとき） | 無言でスポット名が変わる |
| 新規登録の「やめる」 | `disabled` だけで文言が変わらない（同じ画面の「登録しています…」と扱いが違う） |
| しおりのダイアログ 3 つ（期間・メンバー・招待リンク） | `disabled` だけで文言が固定 |
| アルバムの各操作（名前変更・権限変更・メンバー削除・退出） | 招待リンクの発行だけ文言が変わり、ほかは `disabled` だけ |
| 入力欄の候補取得（スポット名・行き先・アルバム名） | 候補が無言で遅れて出る。招待のユーザー名検索は Task 2 で直したので、そこに揃える |

**画面を移るとき（Task 5）**: 要件 4.5.11 の表で「置く」とした 8 枚に `loading.tsx` を置く。

### やらないこと（把握したうえで残す）

| 対象 | 理由 |
|---|---|
| 管理画面すべて | 触るのは管理者だけ。提出後に回す（要件 9 章 未決定事項 No.14） |
| **メニューバーの未読件数** | 背景で 60 秒に 1 回走る。**読み込み表示を足すと画面の端がちらつき続ける**ので、黙って出す方がよい |
| **一覧に戻ったときのページ復元** | 骨組みを出すと、せっかく残した見た目が一度消える。**黙って復元するほうが速く感じる** |
| **見えているのに押せない時間**（最初の HTML が出てから JavaScript が効くまで） | ボタンを無効に見せると「壊れている」印象になる。本番の実測で JavaScript は 9 本・248 KB（圧縮後）、うち 218 KB は React と Next の土台で減らす余地も無い |
| **全画面共通の受け皿（`src/app/loading.tsx`）を 1 枚置く案** | 1 ファイルで広く埋まるが、**どの画面でも同じ形の骨組みが出る**ので、形の合わない画面ではかえって違和感が出る。画面ごとに置く方を採った |
| 関所（`src/proxy.ts`）の問い合わせを減らすこと | 性能改善の Task 3（保留）の範囲 |

上の 3 つ（太字）は「足すと悪くなる」と判断して足さないものなので、**直し忘れと区別が付くようここに残す**（要件 4.5.11 の共通の決まり）。
