# 受入テスト（E2E）の土台（e2e-foundation）

> 出典: [requirement.md](../../requirement.md) 9 章 未決定事項 No.12（2026-11-01 に決着）・8 章 受入条件
> 関連: [development-order.md](../../development-order.md)「テスト基盤について」・[development-process.md](../../development-process.md)「テスト」

## ユーザーストーリー

開発者として、画面をまたぐ動線が壊れたときに自動で気づきたい。なぜなら、いま壊れたことに気づける手段が単体テスト（2,449 件）と自分の手で触ることだけで、**画面・API・データベースを通した動線は触るまで分からない**から。

## 現状（2026-11-01）

| 区分 | 状況 |
|---|---|
| 単体テスト | 整備済み。322 ファイル・2,449 件。CI で毎回走る |
| 結合テスト | 未整備。Supabase を実際に叩くためローカル Supabase（CLI＋Docker）が必要 |
| E2E テスト | **未整備。** 各ストーリーの「受入テスト（E2E）」タスク 36 件は 2026-09-19 に「後回し」として閉じたまま |

単体テストで届かない範囲がはっきりしている。**Route Handler と `async` な Server Component は単体テストの対象外**（Vitest が非同期 Server Component を扱えない。[development-process.md](../../development-process.md)）。つまり API 89 本の入口と、画面を描くサーバー側の処理は、**自動では一度も通されていない**。

## 決めたこと（2026-11-01）

**土台を作り、主導線の代表 4 本だけを通す。** 36 件を一度に戻すと、土台が正しいかを確かめる前にテストの本数で手が止まる。まず「E2E が回る状態」を作る。

土台は 4 つで、要件定義書 9 章 No.12 に書いた想定のとおりにする。

| # | 要るもの | なぜ |
|---|---|---|
| 1 | Playwright | Next.js の同梱ドキュメントが E2E に挙げている道具。Chromium・WebKit・Firefox を同じ書き方で動かせる（要求定義書 3-2 の対応ブラウザが Chrome・Safari・Edge なので、WebKit を動かせることが要る） |
| 2 | ローカル Supabase（CLI＋Docker） | **本番・開発のどちらの DB も使えない。** E2E は毎回データを作って壊すので、本番は当然さわれず、開発用（`tabikoe-dev`）も壊すと画面確認ができなくなる。2026-10-09（#896）に 2 つに分けたのと同じ理由で、**3 つ目として使い捨ての DB が要る** |
| 3 | テスト専用のログイン経路 | ログインは Google の画面を経由するので**自動化できない**（Google 側が自動操作を弾く。やるべきでもない）。`E2E_TEST=1` のときだけ有効になる経路を作り、本番で絶対に有効にならないようにする |
| 4 | Google マップのスタブ | 本物を呼ぶと**課金され、結果が毎回変わり、位置情報の許可ダイアログが出る**。地図の JavaScript をテスト側で差し替える |

### 通す 4 本（代表）

**壊れたら利用者がすぐ困る順**に選んだ。要求定義書 1 章の主導線（探す → 位置を確かめる → 集める → 残す）と、提出後に足した共有を押さえる。

| # | 動線 | 壊れたときの影響 |
|---|---|---|
| 1 | ログインして検索トップに着き、都道府県で探して投稿詳細まで開く | **入口が死ぬ。** 何もできない |
| 2 | 投稿を作って公開し、一覧に出てくる | **このアプリの中心。** 投稿できなければ中身が増えない |
| 3 | 投稿をしおりに入れ、しおり詳細に並ぶ | 旅程を組む機能が死ぬ |
| 4 | 未ログインで共有リンクを開き、投稿が見える | **他人に送ったリンクが開けない。** 気づきにくく、影響が外に出る |

### 決めたこと（やらないことを含む）

- **CI では最初から必須チェックにしない。** E2E はゆらぎやすい。必須にしてから落ちると、再実行で通す癖がつく（[AGENTS.md](../../../AGENTS.md) 約束 23）。**連続して緑になることを確かめてから必須に上げる。** それまでは落ちても止めず、落ちた記録は残す
- **残り 36 件は閉じたままにする。** 土台の上で順に再オープンする
- **結合テスト（ローカル Supabase を直接叩く）は今回やらない。** 土台 2 が同じものを用意するので後から足せるが、**E2E で通る範囲と重なる**ため、先に E2E を通して足りない所を見てから決める
- **ブラウザは Chromium だけで始める。** WebKit を動かせることは土台 1 で確かめるが、4 本を 3 種類で回すと CI の時間が 3 倍になる。**実機の Safari で確かめる手順（390 × 844 のスクリーンショット）は今も残っている**ので、まず Chromium で回す

## 受入条件

- [ ] `npm run test:e2e` でローカル Supabase が立ち上がり、E2E が走って結果が出ること（Task 1・2）
- [ ] テスト専用のログイン経路が `E2E_TEST=1` のときだけ有効で、**設定していない環境では 404 を返すこと**。単体テストでそれを固定すること（Task 3）
- [ ] E2E の実行中に Google Maps・Places・Geocoding・Routes への通信が 1 回も出ないこと（Task 4）
- [ ] 代表 4 本が緑になること（Task 5）
- [ ] CI に E2E のジョブがあり、**落ちても他のジョブとマージを止めないこと**（Task 1）
