# F-PO-01 位置とスポットの指定（中央固定ピン）

> 出典: [requirement.md](../../requirement.md) 3.3.5（v3.0）

## ユーザーストーリー

ログイン済みの利用者として、投稿の位置を地図を動かして決め、その場所に登録済みのスポットがあればそれを、無ければ新しい場所として投稿したい。なぜなら、Google マップに載っていない場所でも名前を調べずに投稿したいから。

> v1 のスポット手動登録モーダル（SC-19、`ManualSpotRegistrationModal`）は廃止し、その地図部分を SC-03 の上 1/3 に移す。v1 の候補検索 UI（Places＋手動登録スポットの統合オートコンプリート、`/api/spots/search`）は「変更」ボタンの先でそのまま使う。

## 詳細

**地図（中央固定ピン）**

- ピンは画面中央に固定し、地図側をドラッグ・ピンチ操作してピンの指す位置（＝投稿の位置）を決める。
- 初期位置は入口により異なる（[post-entry-points.md](post-entry-points.md)）。位置情報が拒否された場合は東京駅周辺を中心に開き、「地図を動かして場所を合わせてください」と案内する。
- 右上の現在地ボタンでいつでも現在地に戻せる。初回だけ「地図を動かしてピンを合わせる」と 1 行表示する。
- 既存スポットを選んでいるときはピンをそのスポットの位置に固定し、地図を動かしても位置は変わらない。「変更」→「新しい場所」で中央固定ピンに戻る。

**スポット名欄**

- 初期値はピンの位置から自動で決める：半径50m以内に登録済みスポット（Google Places由来・手動登録の双方）があればそれを選択済みにし、無ければ「この場所（新しい場所）」とする。
- 「変更」を押すと自前のオートコンプリートUIで候補を表示する（投稿数が多い順、最大5件。Places APIはRoute Handlers経由）。候補を選ぶと地図がそのスポットへ移動し、位置は固定される。
- 「この場所（新しい場所）」のまま投稿すると、ピンの緯度経度でスポットを新規登録する（`spots.source = 'manual'`）。スポット名は任意で、未入力なら「名前のない場所」とし、あとから編集できる。投稿一覧・詳細では「タビコエだけの場所」ラベルを付ける。
- 重複登録の防止：半径50m以内に既存スポットがある場合は新規登録せず、既存スポットへ寄せる（投稿時にサーバー側で再判定する）。
- スポットの新規登録は「投稿する」の時点で行う。下書きは緯度経度だけを持ち、スポットは作らない。
- スポット登録時に Geocoding API で逆ジオコーディングし `spots.prefecture` に保存する（v1 実装済みの `/api/spots/{id}/geocode` を利用）。

## 受入条件

- [ ] SC-03 上部の地図を動かすとピンの指す位置が変わり、その座標が投稿の位置として保存されること
- [ ] 半径50m以内に既存スポットがあればそれが自動で選択され、無ければ「この場所（新しい場所）」になること（受入条件6）
- [ ] 「新しい場所」のまま投稿すると、ピンの位置でスポットが新規登録され、投稿一覧・詳細に「タビコエだけの場所」ラベルが表示されること（受入条件54）
- [ ] 半径50m以内に既存スポットがある位置で「新しい場所」として投稿しても、新規登録されず既存スポットに紐づくこと（受入条件37）
- [ ] 「変更」から名前で候補を検索して選ぶと、地図がそのスポットへ移動し位置が固定されること
- [ ] 位置情報を拒否した場合、東京駅周辺で開き、地図を動かす案内が表示されること
- [ ] スポット手動登録モーダル（SC-19）への導線がどこにも残っていないこと
