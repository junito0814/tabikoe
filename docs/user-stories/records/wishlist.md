# F-RC-05 「行きたい」保存

> 出典: [requirement.md](../../requirement.md) 3.6.4

## ユーザーストーリー

ログイン済みの利用者として、気になったスポットを「行きたい」として保存しておきたい。なぜなら、まだ訪れていない場所も含めて、今後行きたい場所を管理したいから。

## 詳細

| 項目 | 内容 |
|---|---|
| 保存単位 | スポット単位（投稿単位ではない） |
| 保存対象 | 投稿の有無を問わない。Google Places API由来のスポットも保存できる |
| 操作起点 | 投稿カード一覧画面（SC-04）、および投稿詳細画面（SC-05）の両方から保存できる |
| 一覧表示 | 「行きたい」スポット一覧画面（SC-08）で確認できる |
| 投稿がないスポットの表示 | プレースホルダ画像を表示する |
| 地図表示 | 全体マップの「行きたい」タブ、およびマイマップで確認できる |

- `wishlist`テーブルは [table-catalog](../data-model/table-catalog.md) Task5で定義済み。
- 投稿カード一覧画面（SC-04）は `map-search`カテゴリのピン操作（F-MP-03）、投稿詳細画面（SC-05）は `browsing`カテゴリの投稿詳細閲覧（F-VW-01）の成果物であり、本ストーリーはそれぞれの画面に保存ボタンを追加する形で統合する。
- 地図上での表示（全体マップの「行きたい」タブ・マイマップ）は、それぞれ地図・検索機能（F-MP-01）・[my-map](my-map.md)（F-RC-06）側で本ストーリーのデータを参照して描画する。ピンの視覚的区別自体は [pin-display-rules](../shared-ui/pin-display-rules.md) で定義済み。

## 受入条件

- [ ] 投稿カード一覧・投稿詳細のいずれからも、スポットを「行きたい」として保存・保存解除できること
- [ ] 「行きたい」スポット一覧画面で、保存したスポットが一覧表示されること
- [ ] 投稿がないスポットにはプレースホルダ画像が表示されること
- [ ] Google Places API由来のスポット（投稿が存在しない場合を含む）も保存できること
