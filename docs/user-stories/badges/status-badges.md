# F-BG ステータスバッジ

> 出典: [requirement.md](../../requirement.md) 3.7

## ユーザーストーリー

ログイン済みの利用者として、自分の投稿・いいね活動に応じたバッジを獲得し、一覧で確認したい。なぜなら、自分の旅の記録の積み重ねを実感でき、継続のモチベーションになるから。

## 詳細

- バッジ種別と獲得条件は以下のとおり。

  | バッジ種別 | 獲得条件 |
  |---|---|
  | 都道府県バッジ | 該当都道府県で1件以上投稿する |
  | 投稿数バッジ | 累計投稿数1件／10件／50件／100件 |
  | いいね数バッジ | 累計獲得いいね数1件／10件／50件／100件／200件 |

- 都道府県の判定は、投稿に紐づくスポットの緯度経度をもとに行う。スポット登録時、Route Handlers（`/api/spots/{id}/geocode`）がGoogle Maps Geocoding APIをサーバー側で呼び出し、逆ジオコーディングの結果を`spots.prefecture`に一度だけ保存する。**このロジックは[posts/spot-selection](../../tasks/posts/spot-selection/06-prefecture-reverse-geocoding.md)で実装済み**であり、本ストーリーはその結果（`spots.prefecture`）を消費するのみとする。
- `badges`テーブル（`id`, `user_id`, `badge_type`, `acquired_at`、`(user_id, badge_type)`一意制約）は**[data-model/table-catalog](../../tasks/data-model/table-catalog/04-badges-table.md)で定義済み**であり、本ストーリーはそこへの書き込みロジック（判定・INSERT）を実装する。
- ユーザーは、獲得済み・未獲得のバッジをステータスバッジ画面（SC-10）で一覧確認できる。
- バッジを新たに獲得した際は、その場でトースト表示を行う（通知一覧には残さない。3.9参照）。
- 投稿削除により投稿数・いいね数が獲得条件を下回っても、獲得済みバッジは失われない。**このバッジ非削除の保証は[posts/post-delete Task3](../../tasks/posts/post-delete/03-badge-retention-regression-test.md)で回帰テスト済み**であり、本ストーリーでは新たなタスクを設けない。

## 受入条件

- [ ] 都道府県バッジが、スポット登録時のサーバー側逆ジオコーディング結果に基づいて正しく判定されること
- [ ] 投稿数バッジ（1／10／50／100件）が、累計投稿数の到達時点で正しく付与されること
- [ ] いいね数バッジ（1／10／50／100／200件）が、累計獲得いいね数の到達時点で正しく付与されること
- [ ] ステータスバッジ画面（SC-10）で、獲得済み・未獲得のバッジが一覧確認できること
- [ ] バッジを新たに獲得した際、その場でトースト表示され、通知一覧（SC-14）には残らないこと
- [ ] 投稿削除によりバッジの獲得条件を下回っても、獲得済みバッジは失われないこと（[posts/post-delete Task3](../../tasks/posts/post-delete/03-badge-retention-regression-test.md)で担保）
