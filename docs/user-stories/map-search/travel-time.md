# F-MP-06 所要時間の実測（travel-time）

> 出典: [requirement.md](../../requirement.md) 3.4.6・4.5.7・6.7・8章 79（2026-09-25 決定）
> 前身: [feedback-0919.md](../shared-ui/feedback-0919.md) の「移動手段」（v3.2。直線距離からの目安だけだった）

## ユーザーストーリー

旅先で「近くのスポットを探す」を使う人として、表示される所要時間が実際に近い値であってほしい。車で 20 分かかる場所が「約 10 分」と出ると、予定が崩れて使えないから。

## 背景（2026-09-25、ステージングの実機確認で判明）

v3.2 では所要時間を「直線距離 ÷ 速度」で出していた。渋谷・新宿で試すと、車の値が実際の半分ほどになる。原因は 2 つ。

1. 直線距離で計算している（実際の道は 1.3 倍前後）
2. 車の速度 500m／分（時速 30km）が、信号・渋滞のある一般道に対して速すぎる

## 詳細

- 移動手段に**電車**と**バス**を加え、5 つにする（徒歩／自転車／車／電車／バス）。半径は 徒歩 1km／自転車 3km／車 10km／電車 15km／バス 5km。
- **徒歩・車・電車・バスは Google Routes API の実測**にする。徒歩は信号・横断歩道・歩道の経路、車は渋滞、電車・バスは時刻表（出発時刻は「今」）が反映される。
- **自転車だけは目安**。Google が日本で自転車の経路を提供していないため。直線距離 × 1.3（道の曲がりの分）÷ 240m／分（時速 14.4km。信号待ちを含む実勢）で計算する。直線距離あたりに直すと約 185m／分。
- Routes API が失敗・上限・経路なしのときは同じ計算の目安に切り替える（速度は 徒歩 80m／分、車 400m／分、電車 500m／分、バス 300m／分）。利用者にエラーは見せない。
- **表示は「〈移動手段〉 約〈N〉分」で統一する**。「徒歩 約 6 分」「自転車 約 12 分」「車 約 12 分」「電車 約 24 分」「バス 約 18 分」。実測か目安かは区別しない。
- 費用を抑えるため、現在地を約 100m 単位に丸めて同じ地点・同じ移動手段の結果を 10 分間使い回し、1 回の問い合わせは最大 20 件にする。自転車では呼ばない。

## 受入条件

- [ ] 移動手段に電車・バスが増え、選ぶと半径と一覧が変わること
- [ ] 徒歩・車・電車・バスの所要時間が Routes API の値になり、直線距離の計算よりも実際に近いこと（渋谷で 5km 先の地点で確認）
- [ ] Routes API を止めた状態でも画面がエラーにならず、目安の時間が出ること
- [ ] 表示が「徒歩 約 6 分」「自転車 約 12 分」「車 約 12 分」のように統一されていること
- [ ] 同じ地点・同じ移動手段で 10 分以内に開き直したとき、Routes API を呼び直さないこと
