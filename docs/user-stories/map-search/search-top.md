# F-MP-02 検索トップ（ハブ）

> 出典: [requirement.md](../../requirement.md) 3.4.1（v3.0で再定義。v1 の「地名検索」を置き換える）

## ユーザーストーリー

ログイン済みの利用者として、アプリを開いたらすぐに「行き先を入れる」「近くを見る」「いまいる場所に投稿する」のどれかを選びたい。なぜなら、このアプリで何ができるかを迷わず、目的の操作に 1 タップで入りたいから。

## 詳細

- ログイン後の着地点（SC-00、`/`）。置く要素は次の 3 つだけで、地図・一覧・その他の情報は出さない。並びは「行き先の入力欄」→「近くのスポットを探す」→「いまいる場所に投稿する」。
- 行き先の入力欄：プレースホルダ「どこへ行く？」。都道府県名・市区町村名・駅名・スポット名のいずれでも入力できる。
- 候補表示：入力中（300ms debounce）に候補を最大 8 件、種別ラベル付きで表示する。順序は ①都道府県（アプリ内の固定リストの前方一致）②駅・市区町村（Google Places Autocomplete を `/api/geocode/suggest` 経由で、地域・駅の種別に限定。セッショントークンを用いる）③登録済みスポット名（Supabase、投稿数順）。
- 決定時：候補を選ぶ、または入力を決定すると投稿一覧（SC-04）へ遷移する（`/search?pref=`／`?lat=&lng=&q=`／`?spot=`）。候補に無い文字列は Geocoding API で座標化して周辺検索とし、座標化できなければ「見つかりませんでした」と表示する。
- 「近くのスポットを探す」：位置情報の許可を求め、地図を探すモード（[explore-mode](explore-mode.md)）で開く。拒否時は「行き先を入力してください」と表示し入力欄にフォーカスする。
- 「いまいる場所に投稿する」：位置情報の許可を求め、現在地にピンが刺さった SC-03 を直接開く（[post-entry-points](../posts/post-entry-points.md)）。この画面の主要ボタン（アクセント色）。
- 未ログイン時：サービス説明一文（「まだ知られていない場所の、行った人のリアルな声」）とログインボタンだけを表示する（v1 のトップページの役割を引き継ぐ）。
- この画面だけ背景上部に空のグラデーションを敷く（[theme](../shared-ui/theme.md)）。
- v1 の地図上部の検索バー（`PlaceSearchBar`、`/api/geocode`）は撤去する。Geocoding の Route Handler は決定時の座標化に流用する。

## 受入条件

- [ ] ログイン後の着地点が検索トップで、行き先の入力欄・「近くのスポットを探す」・「いまいる場所に投稿する」の 3 つだけが表示されること（受入条件4）
- [ ] 「おおさ」と入力すると、都道府県・駅・スポットの候補が種別ラベル付きで最大 8 件表示され、選ぶと投稿一覧に遷移すること（受入条件5）
- [ ] 候補に無い文字列を決定すると座標化して周辺検索になり、座標化できなければ「見つかりませんでした」と表示されること
- [ ] 「近くのスポットを探す」で位置情報を拒否すると、入力欄にフォーカスして案内が表示されること
- [ ] 未ログイン時はサービス説明一文とログインボタンだけが表示されること
- [ ] Places・Geocoding の API キーがブラウザから確認できないこと（受入条件23）
- [ ] 検索トップから投稿一覧の初回表示が、投稿100件程度の条件下で3秒以内に完了すること（受入条件22）
