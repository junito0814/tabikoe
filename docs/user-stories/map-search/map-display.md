# F-MP-01 地図表示

> 出典: [requirement.md](../../requirement.md) 3.4.1

## ユーザーストーリー

ログイン済みの利用者として、地図上でスポットの投稿状況を一目で把握したい。なぜなら、次にどこへ行くかを地図から直感的に探したいから。

## 詳細

- 1スポットにつき1ピンを表示する。
- 画面上部のタブで「全体」「行きたい」を排他的に切り替える。
  - 「全体」：公開設定が「公開」の投稿があるスポットのピンを表示する。
  - 「行きたい」：ログインユーザー自身が「行きたい」保存したスポットのピンのみを表示する。
- 自分の投稿があり、かつ「行きたい」保存もしているスポットは、「全体」タブ上では通常ピンとして表示する（マイマップ 3.6.5 と同一ルールで統一する）。
- ピンの区別は色および形状・アイコンの両方で行い、色のみに依存しない。
- 同一エリアにピンが集中する場合はクラスタリングして表示する。
- 表示中の地図範囲内のピンを最大100件まで読み込む（`/api/spots`経由）。
- 初期表示位置は、位置情報の利用が許可されている場合は現在地、拒否された場合は東京駅周辺（緯度35.6812、経度139.7671）とする。
- 利用にはログインを必須とする。

> ピンの視覚的区別（アイコン・色定義）は [shared-ui/pin-display-rules](../shared-ui/pin-display-rules.md) の成果物を利用する。「行きたい」タブのデータは [records/wishlist](../records/wishlist.md) の保存データに依存する。

## 受入条件

- [ ] 地図上に現在地が表示され、位置情報が拒否された場合は東京駅周辺が初期表示されること
- [ ] 全体マップで「全体」「行きたい」タブが排他的に切り替わること
- [ ] 同一スポットへの複数投稿が1ピンに集約されること
- [ ] ピンの区別が色のみに依存せず、形状・アイコンでも判別できること
- [ ] 自分の投稿があり同時に「行きたい」保存もしているスポットが、「全体」タブ上で通常ピンとして表示されること
- [ ] 表示中の地図範囲内のピンが最大100件まで読み込まれること
- [ ] マップ画面が、投稿100件程度の条件下で3秒以内に表示されること
