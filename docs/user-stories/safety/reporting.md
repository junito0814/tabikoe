# F-SF-01 通報

> 出典: [requirement.md](../../requirement.md) 3.8.1

## ユーザーストーリー

ログイン済みの利用者として、不適切な投稿・コメント・ユーザー・スポット・アルバムを運営に通報したい。なぜなら、自分では対処できない問題のあるコンテンツについて、運営に対応を求めたいから。

## 詳細

- 通報対象は以下の7種類。
  - 投稿全体
  - 投稿内の個別の写真・動画（何点目かを特定する）
  - 投稿の感想テキスト
  - コメント（個別）
  - ユーザー（アカウント自体）
  - スポット（虚偽登録等）
  - アルバム
- 通報理由の選択肢は、上記の対象に応じて出し分ける。
  - 共通の選択肢：不適切な表現／個人情報の掲載／虚偽の情報／著作権・肖像権の侵害／スパム・宣伝目的／その他
  - 「なりすまし」はユーザー通報時のみ選択可能
  - 「スポット情報の誤り」はスポット通報時のみ選択可能
- 入力は理由の選択（必須）＋自由記述（任意、1,000文字まで）。
- 同一ユーザーが同一対象に重複して通報することはできない。
- 通報後も、管理者が確認するまで対象は通常どおり表示する（自動非表示は行わない）。
- 通報には対応状態を持たせる：未確認／確認中／対応済み（非公開化）／対応済み（削除）／問題なし。対応状態の更新・通報者への通知は管理者機能（F-AD-05 [通報対応操作](../../tasks/admin/report-handling/00-index.md)）の範囲で行う。本ストーリーは通報の作成・保存・重複防止までを対象とする。
- 通報の作成頻度は1ユーザーにつき1日20件までに制限する（7.3準拠）。

## 受入条件

- [ ] 通報画面（SC-11）で、通報対象（投稿全体／写真・動画／感想テキスト／コメント／ユーザー／スポット／アルバム）に応じて通報理由の選択肢が出し分けられること（なりすましはユーザー通報時のみ、スポット情報の誤りはスポット通報時のみ選択可能）（8章 受入条件20）
- [ ] 理由選択（必須）と自由記述（任意、1,000文字まで）で通報を送信できること
- [ ] 同一ユーザーが同一対象に重複して通報できないこと
- [ ] 通報後も対象が自動非表示にならず、通常どおり表示され続けること
- [ ] 1ユーザーにつき1日20件を超える通報が拒否されること
