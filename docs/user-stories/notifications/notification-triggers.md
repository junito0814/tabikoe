# F-NT-01 通知の発生条件

> 出典: [requirement.md](../../requirement.md) 3.9.1（v3.0でしおりの 2 種を追加）

## ユーザーストーリー

ログイン済みの利用者として、自分の投稿へのコメント・いいねやアルバムでの出来事が起きた時に気づきたい。なぜなら、他の利用者との交流や自分の役割の変化を見逃したくないから。

## 詳細

要件定義書3.9.1に定義された10種類（v3.0 でしおりの 2 種を追加）の通知発生条件を、共通の仕組みで一貫して作成する。5.3「通知の実装」の方針に従い、通知の発生元（コメント・いいね等）を扱う各機能のRoute Handlers自身がイベント発生時に`notifications`テーブルへINSERTする（通知作成処理自体を1箇所に集約するのではなく、7.6準拠の共通関数を各機能から呼び出す方式とする）。`notifications`テーブルの定義は[table-catalog](../data-model/table-catalog.md)で完了済みのため、本ストーリーでは対象としない。

3.9.1表の各行の実装状況・担当ストーリーは以下のとおり。

| 通知の種類 | 発生条件 | 担当 |
|---|---|---|
| コメント | 自分の投稿にコメントが付いた時（自分を除く） | browsing/comments（新規作成、本ストーリー範囲外） |
| いいね | 自分の投稿にいいねが付いた時（自分を除く） | browsing/likes（新規作成、本ストーリー範囲外） |
| アルバムへの参加 | 招待リンクを開いてメンバーに加わった時 | records/album-collaboration（新規作成、本ストーリー範囲外） |
| 権限の変更 | オーナーがメンバーの権限を変更した時 | records/album-collaboration（同上） |
| メンバーの削除 | オーナーがメンバーを削除した時 | records/album-collaboration（同上） |
| 新オーナーへの選出 | 3.6.3のルールで自分が新オーナーに選出された時 | **実装済み**。[F-AC-05 Task2: アルバムオーナー継承ロジック](../../tasks/account/account-deletion/02-album-owner-succession.md)が退会処理と同一トランザクションで通知を作成する |
| 運営からのお知らせ | 管理画面からお知らせを配信した時 | admin/announcement-management（新規作成、本ストーリー範囲外）。個人向け`notifications`ではなく`system_announcements`への1件のみのINSERTである点が他と異なる |
| 通報処理結果 | 自分の通報が「削除」で対応された時（「非公開化」「問題なし」は対象外） | admin/report-handling（新規作成、本ストーリー範囲外） |
| しおりへの参加（v3.0） | 招待リンクを開いてしおりのメンバーに加わった時。通知先は参加した本人・オーナー・既存メンバー | itinerary/itinerary-sharing（通知種別カタログに `itinerary_joined` を追加する） |
| しおりからの削除（v3.0） | オーナーがメンバーをしおりから削除した時。通知先は削除された本人 | itinerary/itinerary-sharing（`itinerary_member_removed` を追加する） |

本ストーリーが新規に作る成果物は、上記の各担当機能が呼び出す**通知作成共通関数**と、通知種別（type）・payload・通知先ルールを定義する**通知種別カタログ**の2点のみである。各担当機能自体のRoute Handler実装は、それぞれのストーリーのタスクとして扱う。

## 受入条件

- [ ] 各機能のRoute Handlerが、共通の通知作成関数を通じて`notifications`へ書き込む構成になっていること（直接INSERTを重複実装しないこと）
- [ ] コメント・いいね・アルバム参加・権限変更・メンバー削除・新オーナー選出のいずれについても、行為者本人には通知が作成されないこと（自分自身の操作を除く）
- [ ] 運営からのお知らせは、`notifications`ではなく`system_announcements`へ1件のみ記録され、ユーザーごとに複製されないこと
- [ ] 通報対応が「削除」の場合のみ通報者へ通知が作成され、「非公開化」「問題なし」の場合は作成されないこと
- [ ] しおりへの参加・しおりからの削除が通知種別カタログに定義され、通知一覧に表示されること（受入条件29）
- [ ] 「まだあった」報告としおりのチェックでは通知が作成されないこと
