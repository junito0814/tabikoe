# F-NT-02 通知一覧画面

> 出典: [requirement.md](../../requirement.md) 3.9.2

## ユーザーストーリー

ログイン済みの利用者として、自分宛の通知と運営からのお知らせを1つの画面でまとめて確認したい。なぜなら、複数の情報源を別々に確認する手間をなくし、重要な連絡を見逃さないようにしたいから。

## 詳細

- 個人向け通知（`notifications`）と運営からのお知らせ（`system_announcements`）を新着順に統合表示する画面（SC-14）。
- お知らせには種別ラベル（「お知らせ」）を付けて区別し、個人向け通知と時系列順に混在させる。
- 未読／既読は個人向け通知のみが持つ状態。通知一覧を開くと、表示された個人向け通知は既読になる。既読化に伴い、メニューバーの未読件数バッジ（[shared-ui/menu-bar Task2](../../tasks/shared-ui/menu-bar/02-unread-notification-badge.md)で表示・取得APIは実装済み）を更新する。
- お知らせは全ユーザー共通のレコードのため個別の既読管理は行わない。常に表示し、未読件数の集計対象にも含めない。新着のお知らせは一覧内で視覚的に強調表示する。
- 通知の種類に応じて、タップ時に関連する画面（アルバム画面、投稿詳細画面等）へ遷移する。
- 1回につき20件を読み込み、スクロールに応じて追加読み込みする（無限スクロール）。
- 保存期間：90日を超えた通知は表示対象から除外する。**TBD**：お知らせにもこの90日ルールが適用されるか、また非表示のみか物理削除も行うかは要件定義書9章 未決定事項#3で未確定。本ストーリーでは個人向け通知のみに90日フィルタを適用し、お知らせは対象外（常に表示）として実装し、方針確定後に見直す前提とする。

## 受入条件

- [ ] 個人向け通知とお知らせが新着順に統合表示され、お知らせに種別ラベルが付与されること
- [ ] 通知一覧を開くと、表示された個人向け通知が既読になり、メニューバーの未読件数バッジが更新されること
- [ ] お知らせは既読管理の対象外として常に表示され、未読件数の集計に含まれないこと
- [ ] 通知の種類に応じて、タップ時に関連する画面へ遷移すること
- [ ] 1回につき20件を読み込み、スクロールに応じて追加読み込みされること
- [ ] 90日を超えた個人向け通知が一覧の表示対象から除外されること
