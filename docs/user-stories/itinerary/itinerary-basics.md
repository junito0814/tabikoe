# F-IT-01 しおりの作成・一覧・削除

> 出典: [requirement.md](../../requirement.md) 3.11.1, 3.11.8（v3.0で新設）

## ユーザーストーリー

ログイン済みの利用者として、旅行タイトルを付けたしおりを作り、集めたスポットを旅行ごとにまとめたい。なぜなら、Google マップの保存リストのように、旅行前の計画を 1 か所に持っておきたいから。

## 詳細

- 作成の起点：保存先シートの「＋ 新しいしおりを作る」（[wishlist](../records/wishlist.md)）、しおり一覧（SC-22）の「＋ 新規」。入力は旅行タイトル（必須、200文字まで）と期間（任意。開始日〜終了日。後から設定・変更できる）。
- 旅行 ID との関係：しおりは旅行（`trips`）と 1 対 1（`itineraries.trip_id` UNIQUE）。作成時に同名の旅行が自分のものとして既にあればそれに紐づけ、無ければ新しい旅行 ID を作る（[trip-title](../posts/trip-title.md) の一致判定に従う）。1 つの旅行にしおりは 1 つまで。
- 作れる人：旅行のオーナーのみ。作成時に `itinerary_members` に owner として自動追加する。アルバムの編集者・閲覧者はその旅行のしおりを作れず、しおりのオーナーから招待されて参加する（[itinerary-sharing](itinerary-sharing.md)）。
- アルバムとの導線：しおり詳細に「アルバムを見る」（同じ旅行 ID のアルバムに投稿があるとき）、アルバム画面に「しおりを見る」（しおりがあり、自分がそのメンバーのとき）。
- 旅行タイトルの変更はしおり・アルバムの両方に反映する。変更できるのは旅行のオーナーのみ。
- 一覧（SC-22、`/itineraries`）：メニューバーの「しおり」から開く。自分がオーナーまたはメンバーのしおりを、期間が近い順（期間未設定は更新日時順）に並べる。各行は旅行タイトル・期間（未設定なら「期間未設定」）・スポット数・済み件数。写真は置かない。期間を過ぎたしおりは末尾に薄く表示し「アルバムを見る」を出す。0 件時は「しおりがありません。投稿一覧の「＋」から作れます」。
- 削除：オーナーのみ。しおり詳細の右下。確認ダイアログに「同じ旅行のアルバム（投稿）は残る」旨を書く。削除してもそのスポットが行きたいや他のしおりに入っていればそちらには残る。
- データの整合：スポットが管理者により削除された場合はしおりからも外す。投稿の削除ではチェック・スポットを変えない。アルバムが投稿 0 件でもしおりは残る。
- 上限：しおり数・スポット数に上限は設けない（実装上の安全弁として各 100 件）。

## 受入条件

- [ ] 保存先シートの「＋ 新しいしおりを作る」およびしおり一覧の「＋ 新規」で、旅行タイトルと期間を指定してしおりを作れ、同名のアルバムと同じ旅行 ID で紐づくこと（受入条件57）
- [ ] しおり一覧がメニューバーから開け、期間が近い順に並び、期間を過ぎたしおりが末尾に薄く表示されて「アルバムを見る」が出ること（受入条件65）
- [ ] 旅行のオーナー以外がその旅行のしおりを作れないこと。1 つの旅行に 2 つ目のしおりを作れないこと
- [ ] 旅行タイトルを変更するとしおりとアルバムの両方に反映されること
- [ ] しおりを削除しても同じ旅行のアルバム（投稿）と、他のしおり・行きたいのスポットが残ること
- [ ] アルバム画面の「しおりを見る」がしおりのメンバーにだけ表示されること
