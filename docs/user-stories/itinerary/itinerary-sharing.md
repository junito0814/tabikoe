# F-IT-07 しおりの共有・招待

> 出典: [requirement.md](../../requirement.md) 3.11.7（v3.0で新設）

## ユーザーストーリー

旅行を計画する利用者として、同行者をしおりに招待して一緒にスポットを足したりチェックしたりしたい。なぜなら、旅の計画も記録も同じ仲間で共有したいから。

> アルバムの招待（[album-collaboration](../records/album-collaboration.md)、`album_invitations`／`album_members`、招待リンクの Route Handlers と `/invitations/[token]`）と同じ仕組みを、しおり用に独立して持つ。

## 詳細

- 権限はオーナー／メンバーの 2 段階。閲覧専用の権限は設けない。
- オーナー：しおりの作成者（＝旅行のオーナー）。招待リンクの発行・無効化、メンバーの削除、期間の変更、旅行タイトルの変更、しおりの削除ができる。メンバーができることもすべてできる。
- メンバー：スポットの追加・削除・Day と到着予定時刻の変更・並び替え・メモ・チェックができる。自分の意思で退出できる。
- 招待方法：オーナーが「⋯」→「招待」から招待リンクを発行する（`itinerary_invitations`）。有効期限は 7 日間で、オーナーはいつでも無効化できる。発行は 1 ユーザーにつき 1 時間 10 件まで。
- 受諾：リンク（`/itinerary-invitations/[token]`）を開いたユーザーがログインするとメンバーに加わる。参加時に本人・オーナー・既存メンバーへアプリ内通知（[notification-triggers](../notifications/notification-triggers.md)）。メンバー削除時は本人へ通知。
- 見える範囲：しおりはオーナーとメンバーにだけ見える（RLS・Route Handlers の両方）。同じ旅行のアルバムのメンバーであっても、しおりに招待されていなければ見えない（アルバム画面の「しおりを見る」も出さない）。しおりのメンバーとアルバムのメンバーは別に管理し、招待も別々に行う。
- オーナーの退会：旅行のオーナー継承（3.6.3）と同じ処理でしおりのオーナーも新オーナーへ移す。メンバーが誰もいなければしおりは削除する。
- ブロック：ブロック関係にあるメンバー同士でも、しおり内では互いの操作結果が見える（アルバムと同じ扱い）。

## 受入条件

- [ ] しおりのオーナーが招待リンクを発行し、リンクを開いたユーザーがメンバーになれること。アルバムのメンバーであってもしおりに招待されていなければしおりが見えないこと（受入条件64）
- [ ] 招待リンクが発行から 7 日で無効になり、オーナーが手動で無効化できること
- [ ] メンバーがスポットの追加・Day・時刻・メモ・チェックを操作でき、招待・メンバー削除・期間変更・しおり削除はできないこと
- [ ] メンバーが退出でき、しおりへの参加・削除が通知されること
- [ ] オーナーが退会すると、アルバムと同じ継承ルールでしおりのオーナーが移ること
