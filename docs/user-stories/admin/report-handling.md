# F-AD-05 通報対応操作

> 出典: [requirement.md](../../requirement.md) 3.10.5

## ユーザーストーリー

管理者として、通報された対象に対して非公開化・削除・問題なしのいずれかの対応を行いたい。なぜなら、通報内容を精査した上で、サービスの健全性を保ちつつ過剰な対応を避けたいから。

## 詳細

- 管理者は、通報対象に対して以下いずれかの対応を行える。
  - 非公開化：投稿・コメント等を一般ユーザーから見えなくする。復元できる。
  - 削除：投稿・コメント等を削除する。復元できない。この対応の場合のみ、通報者へアプリ内通知を送る（3.8.1、3.9.1参照）。
  - 問題なし：通報を却下し、対象はそのまま表示を続ける。
- ユーザー・スポット・アルバムへの通報の場合、対応は次のように読み替える：ユーザー→アカウントの一時停止、スポット→当該スポット情報の非公開化、アルバム→当該アルバムの非公開化。
- いずれの対応も、対応した管理者・対応日時・対応理由（任意メモ）を`reports`テーブルに記録する。
- 通知の発火（削除時のみ通報者へ通知）は、通知機能が提供する共通の通知作成処理（F-NT-01、[notifications/notification-triggers](../../tasks/notifications/notification-triggers/00-index.md)）を呼び出す形で実装し、本ストーリーでは通知ロジック自体は再実装しない。
- 被通報者への通知は行わない（匿名性の担保のため）。
- Supabase管理コンソールから直接データを操作する運用は、通知の発火を伴わないため原則行わない。

## 受入条件

- [ ] 通報対象に対して「非公開化」「削除」「問題なし」のいずれかの対応を実行できること
- [ ] 「非公開化」で対応した対象が、一般ユーザーから見えなくなり、かつ復元できること
- [ ] 「削除」で対応した対象が削除され、復元できないこと。この対応の場合のみ通報者へアプリ内通知が送られること
- [ ] 「問題なし」「非公開化」の場合は通報者へ通知が送られないこと。被通報者への通知はいずれの対応でも送られないこと
- [ ] 対応した管理者・対応日時・対応理由（任意メモ）が記録されること
- [ ] ユーザー・スポット・アルバムへの通報について、それぞれ規定の対応（アカウント一時停止／スポット非公開化／アルバム非公開化）に読み替えられること
