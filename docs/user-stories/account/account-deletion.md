# F-AC-05 退会

> 出典: [requirement.md](../../requirement.md) 3.2.5

## ユーザーストーリー

ログイン済みの利用者として、アカウントを削除（退会）したい。なぜなら、サービスの利用をやめたいが、その際に自分の投稿やアルバムがどう扱われるかを事前に理解した上で安心して手続きしたいから。

## 詳細

- 処理：ユーザー名を「退会済みユーザー」に、アイコンをデフォルト画像に即座に置き換える。
- 残存データ：投稿、コメント（いずれも投稿者表示のみ匿名化）。
- 削除データ：いいね、「行きたい」保存、ブロック情報（自分が設定した／された双方）、IdP連携情報。
- アルバムオーナーだった場合は、退会処理の一環として3.6.3のオーナー継承ルールに従い新オーナーを自動選出する。
- 退会後、プロフィール画面は非表示となる。
- 退会済みアカウントの投稿に関する削除依頼は、問い合わせ窓口で個別に受け付ける。
- 退会実行前に、投稿・コメントは残るがユーザー名は匿名化される旨、およびオーナーを務めるアルバムがある場合はオーナー権限が自動的に移譲される旨を明示した確認ダイアログを表示する。
- `is_admin`フラグを持つユーザーが退会する場合、事前に他の管理者へフラグを引き継ぐ運用上の確認を必須とする（9章「未決定事項」参照）。

## 受入条件

- [ ] 退会実行前に、データの扱いを説明する確認ダイアログが表示されること
- [ ] 退会後、ユーザー名が「退会済みユーザー」、アイコンがデフォルト画像になること
- [ ] 退会後も投稿・コメントは残存し、投稿者表示のみ匿名化されること
- [ ] 退会に伴い、いいね・「行きたい」保存・ブロック情報・IdP連携情報が削除されること
- [ ] アルバムオーナーが退会すると、投稿数が最も多いメンバーが自動的に新オーナーになること（同数の場合は参加日時が最も早いメンバー）
- [ ] 退会後、プロフィール画面が非表示になること
- [ ] 管理者アカウントの退会時、他の管理者への引き継ぎ確認が必須となること
