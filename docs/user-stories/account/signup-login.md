# F-AC-01 サインアップ・ログイン

> 出典: [requirement.md](../../requirement.md) 3.2.1

## ユーザーストーリー

未ログインの利用者として、Googleアカウントでサインアップまたはログインしたい。なぜなら、パスワードを新たに管理することなく、すぐにサービスを使い始めたいから。

## 詳細

- ログイン方法はGoogleの1つの外部IdPのみ。
- 画面はアカウント新規作成（SC-20）とログイン（SC-01）に分かれる。SC-20にのみ利用規約・個人情報保護方針への同意欄と「アカウントを作成」ボタンを置き、SC-01はログインボタンのみとする。SC-20 から SC-01 への導線（「すでにアカウントをお持ちの方はログイン」）は置くが、SC-01 から SC-20 への導線は置かない（未登録者はログイン後に自動で SC-20 へ。2026-09-22 に変更）。
- 処理フロー：ブラウザ→GoogleのOAuth→Supabase Authへのコールバックを、Route Handlers（`/api/auth/callback`）で受け取りセッションを確立する。
- 初回ログイン時は、IdPから取得した表示名・アイコン画像を、ユーザー名・アイコンの初期値として設定する。
- 取得する情報は、IdPのユーザー識別子、表示名、アイコンURL、メールアドレスに限る。
- アカウント新規作成時、利用規約と個人情報保護方針を別々のチェックボックスにし、両方への同意を必須とする。どちらかでも未チェックならボタンを押せず、サーバー側でもアカウントを作成しない（2026-09-22 に 2 チェックへ変更）。
- 作成が終わったらログイン画面を挟まず、そのままホーム（SC-00）へ移る。2 回目以降はログイン画面からログインする。
- どちらの画面から来てもIdP認証のフローは同一のため、アカウントの有無はコールバック側で判定する。アカウントが無い状態でログイン画面から認証を通った場合は、同意を得ていないためアカウントを作成せず、セッションを破棄してアカウント新規作成画面へ誘導する。
- **ログイン後の着地点（v3.0）**：ログイン完了後は検索トップ（SC-00、[search-top](../map-search/search-top.md)）へ遷移する（v1 の `/map` から変更。`post-login-redirect.ts` を差し替える）。未ログインの SC-00 はサービス説明一文とログインボタンだけを表示する。

## 受入条件

- [ ] ログイン完了後の着地点が検索トップ（SC-00）であること（受入条件4）
- [ ] Googleでサインアップ・ログインが一連で動作すること
- [ ] 初回ログイン時、IdPの表示名・アイコンがユーザー名・アイコンの初期値として設定されること
- [ ] 同意せずにサインアップ操作を行った場合、アカウントが作成されないこと
- [ ] アカウント新規作成画面にのみ同意欄（2 つのチェック）が表示され、ログイン画面には表示されないこと。SC-20 から SC-01 へ遷移でき、SC-01 に SC-20 への導線が無いこと
- [ ] 利用規約・個人情報保護方針の両方にチェックしないとアカウントを作成できず、作成後はログイン画面を挟まずホーム（SC-00）に着くこと
- [ ] アカウントが無い状態でログイン画面から認証を通った場合、アカウントが作成されず、アカウント新規作成画面へ誘導されること
- [ ] 同一IPアドレスからのログイン試行が1分間に10回を超えた場合、リクエストが拒否されること（rate_limitsテーブルで判定）
