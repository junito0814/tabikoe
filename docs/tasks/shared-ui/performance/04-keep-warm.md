## 背景

ホーム画面のアイコンから開くと**毎回 3 秒ほど**かかると報告があり（2026-10-02）、実測した（iPhone 相当・4G 相当・CPU を 4 倍遅く、未ログインのホーム）。

| | しばらく開いていないとき | 続けて開いたとき |
|---|---|---|
| HTML が届くまで | 793ms | 172〜224ms |
| 最初の描画 | **2192ms** | 764〜904ms |
| 読み込み完了 | 2439ms | 897〜1105ms |

**差のほとんど（+620ms）は HTML が届くまでの時間に出ている。** アプリ側の処理ではなく、**Vercel の関数が冷えていること**が主因。JavaScript 344KB・フォント 120KB の影響は 140ms 程度しかなく、削っても体感は変わらない。

**「毎回遅い」と「原因はコールドスタート」は矛盾しない。** 本サービスは利用者が少ないため、関数が温かいままの時間を超えた間隔で開かれる。つまり**ほぼ毎回冷えている**。

## 実装内容

GitHub Actions の定期実行で、**5 分おきに本番のホームを 1 回叩く。**

```
.github/workflows/keep-warm.yml
```

- `schedule:` の cron で 5 分おき
- `curl` で `https://tabikoe.vercel.app/` を 1 回叩くだけ
- **ホーム（`/`）だけでよい。** 関所（`src/proxy.ts`）を通り、Supabase への接続まで温まる
- 失敗しても CI を赤くしない（`|| true`）。温めは「できれば」の処理で、落ちても困らない
- 手で走らせられるように `workflow_dispatch:` も付ける（展示・審査の直前用）

### 気をつけること

- **GitHub Actions の `schedule` は混雑時に遅れる。** 5 分おきと書いても実際は 10〜15 分空くことがある。それでも「何時間も冷えたまま」よりはるかに良い
- **Supabase の無料プロジェクトは使われないと一時停止する。** これも同時に防げる（副次的な効果だが大きい）
- **叩くのは公開されているホームだけ**。ログインが要る画面は叩かない（認証情報を CI に置かない）
- 本番だけを対象にする。プレビューは温めない

### やらないこと

- **Vercel の Cron は使わない。** 無料プランでは 1 日 1 回までで、5 分おきにできない
- **Service Worker で殻をキャッシュする**案は見送る。ホームはログイン状態で中身が変わるのでキャッシュが難しく、作りを大きく変えることになる（2026-10-02 に判断）
