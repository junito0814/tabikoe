## 実装内容

**壊れたら利用者がすぐ困る順**に 4 本書く。要求定義書 1 章の主導線（探す → 位置を確かめる → 集める → 残す）と、提出後に足した共有を押さえる。

| # | 動線 | 確かめること |
|---|---|---|
| 1 | 入口 | ログインして検索トップに着き、**都道府県から探して**一覧 → 投稿詳細まで開ける。詳細に写真・スポット名・費用・訪問日が出る |
| 2 | 投稿 | 投稿を作って公開し、一覧に出てくる。**必須項目が空では公開できない**ことも見る |
| 3 | しおり | 投稿詳細からしおりに入れ、しおり詳細の Day に並ぶ |
| 4 | 共有 | 公開した投稿の共有リンクを**ログアウトした状態で**開き、投稿が見える |

**行き先は自由入力ではなく都道府県から選ぶ。** 自由入力はスポット候補（Places）を叩くので、スタブの出来に結果が左右される。**入口が生きているかを見たいだけ**なので、外部に寄りかからない道を通す。

**スポットは手入力で作る。** 同じ理由。既存スポットを選ぶ道は種データの 2 件で通す。

書き方の決まり:

- **要素は見える文字と役割（role）で探す。** CSS のクラス名で探すと、見た目を直すたびにテストが落ちる
- **待つのは「出ること」で、時間ではない。** `waitForTimeout` を使わない（ゆらぎの元。約束 23）
- **各本の最初に種データを入れ直す**（Task 2 の作り直し）。本の順番で結果が変わらないようにする
- 1 本ごとに**どの受入条件に当たるか**をテストの冒頭コメントに書く（要件定義書 8 章の番号）
