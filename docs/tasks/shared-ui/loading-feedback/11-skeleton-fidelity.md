## 背景

2026-10-02 に 2 つの指摘を受けた。どちらも**骨組みは出ているのに、うまく働いていない**という話。

### 1. 「読み込んでいる感じがしない」

調べたところ、**骨組みが悪いのではなく動きが遅すぎた。**

Tailwind の `animate-pulse` は **2 秒かけて**透明度を 1 → 0.5 → 1 に戻す。ところが実際の待ちは **0.5〜1.5 秒**で、**1 周期の半分も進まないうちに終わる**。0.6 秒の待ちでは透明度が 1 から 0.9 程度までしか動かない。**ほぼ止まって見えていた。**

### 2. 「読み込みが終わるとタイトルが動く」

骨組みと本物を突き合わせたところ、しおり・通知・マイページで**4 つ同時にずれていた**。

| | 骨組み | 本物 |
|---|---|---|
| タイトルの位置 | **中央** | **左** |
| タイトルの大きさ | 16px | **18px** |
| 幅 | `max-w-[560px]` | **`max-w-[520px]`** |
| 左右のボタン | 灰色の枠が左右に 1 つずつ | 通知・マイページには**無い** |

**マイページはさらにひどい。** 骨組みは「マイページ」と出すが、**本物にその見出しが無い**（アイコン＋ユーザー名が出る）。読み込みが終わるとタイトルごと消えていた。

中身の形もずれていた。骨組みのカードは**投稿カードの形**（サムネイル＋行）だが、通知は「丸＋テキスト」、マイページは「プロフィール＋サマリー＋メニュー＋投稿一覧」。

## 実装内容

### 11-1. シマー（`src/components/skeleton/Skeletons.tsx`・`src/app/globals.css`）

`SkeletonBlock` の動きを、透明度の明滅から**光が左から右へ流れる形**に変える。

- 周期 **1.2 秒**
- `prefers-reduced-motion` のときは止める
- **`SkeletonBlock` 1 か所の変更で全画面に効く**

**なぜシマーか** ── 光に**方向がある**ので「働いている」と読める。透明度の明滅には方向が無い。待ちが短くても「半分まで流れた」ことが見える。

**「loading…」の文字は骨組みに重ねない**（要件 4.5.11）。1 つの待ちに 2 つの合図が重なるため。

### 11-2. 3 画面の骨組みを本物と同じ形にする

**今回は 3 画面だけ**（しおり一覧・通知・マイページ）。残り 5 画面（アルバム一覧・行きたい・検索結果・アルバム詳細・しおり詳細）は**実機で確かめてから広げる**（2026-10-02 の判断。提出が 2026-10-07 のため）。

共通: 外枠は `flex min-h-screen flex-col items-center bg-app px-4 py-6` ＋ `max-w-[520px]`。

| 画面 | 上の帯 | 中身 |
|---|---|---|
| **通知** | **左寄せ 18px**「通知」のみ（戻る・右のボタンは**無い**） | 丸（10px）＋ 2 行（本文 13px・日時 11px）の行を 4 つ。`gap-2` |
| **しおり一覧** | 左寄せ 18px「しおり」＋ **右に「＋ 新規」の丸ボタン**（h-9） | 「行きたいスポット」の 1 行 ＋ カード（題名・期間・スポット数）を 3 つ。`gap-2.5` |
| **マイページ** | **見出しを出さない** | プロフィール（丸 64px ＋ 名前 ＋ リンク）／サマリー 2 枚（`grid-cols-2`）／メニュー（1 行 ＋ 2 列 4 つ）／投稿カード 2 枚。`gap-5` |

**マイページで見出しを出さないのが肝。** 本物に無いものを骨組みで見せると、終わった瞬間に消える。

### 11-3. 既存の `ListScreenSkeleton` は残す

まだ 5 画面が使っている。**今回触らない**（それらを直すときに一緒に考える）。
