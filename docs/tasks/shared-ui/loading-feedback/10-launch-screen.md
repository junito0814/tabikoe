## 背景

**場面 1 は 2 回直して 2 回効かなかった。** 3 回目に原因を突き止めた。

| 試したこと | 結果 |
|---|---|
| マニフェストの `background_color` を青に（PR #615） | iOS はマニフェストの背景色を起動画面に使わない |
| `apple-touch-startup-image` 8 枚（PR #636） | 効かない |
| 11 枚に増やし `apple-mobile-web-app-capable` を追加（PR #640） | 効かない |

2026-10-02 に実機（iPhone 17）で `matchMedia()` に直接問い合わせたところ、**すべて揃っているのに出ない**ことが確定した（端末は 402 × 874 @3、一致する宣言あり、画像も HTTP 200 で配信、meta もあり、アイコンも入れ直し済み）。

**`apple-touch-startup-image` という仕組みそのものが、この iOS で働いていない。**

**あわせて矛盾が見つかった。** マニフェストは `theme_color: #2F7FD8`（青）と宣言しているのに、`layout.tsx` の `viewport.themeColor` が白を出しており、**meta がマニフェストを上書きしていた**。同じ PR #615 の中で、入れた青を自分で塗り戻していた。

## 実装内容

### 10-1. `theme-color` をブランドの色に揃える（`src/app/layout.tsx`）

`viewport.themeColor` を、マニフェストと同じ考えに揃える。

| | 色 |
|---|---|
| ライト | `#2F7FD8`（`BRAND_GROUND`。ホーム画面のアイコンと同じ） |
| ダーク | `#0e1e3d`（ダークの `--sky` の最上部） |

値は `src/lib/theme/colors.ts` に定数として置き、CSS との食い違いをテストで止める（既存の `BRAND_GROUND` と同じやり方）。

**副作用を承知のうえでの変更。** `theme-color` は上の帯の色にもなるので、**ライトでは普段も青い帯が見える**。ダークの `#0e1e3d` は地の `#0b1220` とほぼ同じなので気づかない。白いままにするより良いと判断した（白は意図した見た目ではなく、上書きによる事故）。

### 10-2. ロゴ入りの覆いを HTML に直接書く（`src/app/layout.tsx`）

**外部ファイルを 1 つも待たずに描けること**が最優先。そのために次をすべて守る。

- **インラインの `<style>`**（外部 CSS の往復を待たない）
- **`<body>` の先頭**（他の要素の構築を待たない）
- **インライン SVG**（画像ファイルの往復を待たない）
- **JavaScript を使わない**（344KB の読み込みと実行を待たない）
- Server Component のまま（`"use client"` にしない）

**動き**

| 段階 | 時間 | 中身 |
|---|---|---|
| 保持 | 300ms | 青（ダークは紺）＋中央にロゴ。**動かさない**（Instagram と同じ「静かに待つ」形） |
| 去る | 250ms | 軽く拡大しながらフェード |

CSS の `animation` だけで行い、終わったら `pointer-events: none` にして下を触れるようにする。`prefers-reduced-motion` のときは拡大せずフェードのみ。

**なぜ「動かさない」のか** ── 描画が始まる前は何も出せないので、**入場の動きを見せる余地が無い**。Netflix・Twitter 型（音や鳥が迫る演出）は、待ち時間を埋めるのではなく**作っている**。Instagram 型の「静止して待ち、去るときだけ動く」が、この制約に合う（2026-10-02 に利用者と合意）。

### 10-3. 起動画像は残す（`src/app/layout.tsx`・`public/splash/`）

効かないと分かった 10 枚（約 300KB）と宣言は**消さない**。

- 実行時に読み込まれない（iOS が要求したときだけ）ので速度に影響しない
- iPad や別の iOS 版では効く可能性がある
- 提出 5 日前に無用な差分を出さない

**ただし「この端末では効かない」ことを `splash.test.ts` のコメントに残す**（直し忘れと区別が付かなくなるため）。

## 実装して分かった制約（2026-10-02）

本番の HTML を測ったところ、**覆いより前に外部 CSS が 2 本ある**。

```
覆いより前の外部 CSS: 2 本
覆いの位置: 先頭から 5052 バイト（全体 23618 バイト）
```

**ブラウザはすべての外部 CSS が届くまで最初の 1 ピクセルも描かない。** 覆いを `<body>` の先頭にインラインで置いても、**中身とまったく同じ瞬間にしか出せない**。この CSS は Next.js が生成するもので、外すと画面全体が崩れる。

**つまり「押した瞬間からロゴ」は Web では実現できない。** 実現できるのは `apple-touch-startup-image`（この iOS では死亡）かネイティブアプリ（やらないと決定）だけ。

**それでも上の作りは要る。** 押した瞬間からの地の色は `theme-color` が担い、CSS が届いてからの受け渡しは覆いが担う。**白はどちらにしても出ない**ので、目的は達成される。

なお「JavaScript を待たない・画像ファイルを待たない」という条件は**引き続き意味がある**（JavaScript 344KB とフォント 120KB は CSS より遅れて届くため）。外部 CSS だけが越えられない壁だった。
