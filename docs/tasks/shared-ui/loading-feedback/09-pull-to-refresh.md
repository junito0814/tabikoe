# Task 9: 引っ張って更新

> 出典: [loading-feedback.md](../../../user-stories/shared-ui/loading-feedback.md)
> インデックス: [loading-feedback](00-index.md)
> 要件定義書 4.5.11 の場面 6、8 章 96

## 依存

なし

## 背景

ホーム画面から単独のアプリとして開くと、**ブラウザの枠ごと「引っ張って更新」も消える**（実機で確認）。アドレスバーも再読み込みボタンも無いため、**自分で最新にする手段が 1 つも無くなる**。

別の画面へ移って戻れば取り直されるので詰むことはないが、「最新にしたい」と思ったときに何もできない。

## 実装内容

一覧のいちばん上で下に引くと、歯車が回って取り直す。

- 対象は **6 画面**: 通知・マイページ・しおり一覧・アルバム一覧・行きたい・検索結果
- **付けない 3 枚**: スポット別の投稿一覧・投稿詳細・しおり詳細。上 1/3 地図＋下 2/3 シートが `scroll-snap` の入れ物になっており（要件 4.5.6）、**いちばん上で下に引く動きが既に「地図を出す」の意味を持っている**。同じ操作に 2 つの意味を重ねない
- 管理画面にも付けない（保留。要件 9 章 未決定事項 No.14）

### 作り方

共通のフックか包みにまとめ、6 画面から使う（同じものを 6 か所に書かない）。

1. **いちばん上にいるときだけ**反応する（`scrollTop` が 0）
2. 指の動きに合わせて歯車が下りてきて、**引いた距離に応じて回る**
3. しきい値（60px 程度）を超えて離したら `router.refresh()`
4. 取り直している間は歯車を回し続け、終わったら戻す
5. しきい値に届かずに離したら、何もせず戻す

### 気をつけること

- **誤爆させない。** 普通に上へスクロールしただけで反応すると、勝手に読み込み直す壊れたアプリに見える。**しきい値と指の速度は実機で調整する**
- **無限スクロールと喧嘩させない**（`use-infinite-scroll.ts`）。下端の追加読み込みとは別の動き
- ブラウザの跳ね返りを止める必要があるかは実機で見る（`overscroll-behavior`。ホーム画面では既に使っている）
- `prefers-reduced-motion` のときは歯車を回さず、出すだけにする

## テスト要件

### 単体テスト
- いちばん上にいないときは反応しないこと
- しきい値を超えて離したときだけ取り直しが呼ばれること。届かなければ呼ばれないこと
- 取り直している間は二重に走らないこと
- `prefers-reduced-motion` のときは歯車が回らないこと

### 結合テスト
- なし

### E2Eテスト
- **実機で確かめる**（要件 8 章 96）。①6 画面で引っ張ると歯車が回って取り直される ②**付けない 3 枚では今までどおりシートの動きになる** ③普通にスクロールしただけでは反応しない

## 関連する受入条件
