# Task 6: 画面の拡大（ズーム）の扱いをそろえる

> 出典: [loading-feedback.md](../../../user-stories/shared-ui/loading-feedback.md)
> インデックス: [loading-feedback](00-index.md)
> 要件定義書 4.5.12、8 章 92・93

## 依存

なし

## 背景

ホーム画面から単独のアプリとして開くようにした（Task 1）ことで、指での拡大が目に付くようになった。実機で確かめたところ 3 種類あり、原因も止め方も別々。

| # | 何が起きるか | 原因 |
|---|---|---|
| 1 | 入力欄にカーソルを置くと**勝手に拡大され、戻らない** | iOS は 16px 未満の入力欄で自動拡大する。このアプリの入力欄は 11〜14px |
| 2 | ダブルタップで拡大される | ブラウザの既定 |
| 3 | 指 2 本で拡大できる | ブラウザの既定 |

## 実装内容

### 6-1. 入力欄を 16px にする

`<input>` と `<textarea>` の文字を **16px** にする。26 か所。

- 個別に直すのではなく、**`globals.css` にまとめて効かせる**（`input, textarea, select { font-size: 16px }`）。1 か所で決めれば、あとから入力欄が増えても同じになる
- **見た目が変わる**ので、変わり方を実機サイズのスクリーンショットで確かめる。入力欄だけが少し大きくなる
- 認証アプリの 6 桁の入力欄（24px）のように既に 16px 以上のものは変わらない

### 6-2. ダブルタップの拡大を止める

`globals.css` に **`touch-action: manipulation`** を効かせる。

- ダブルタップの拡大が止まる
- あわせて**タップの反応が速くなる**。ブラウザは「2 回目のタップが来るか」を待つために反応を遅らせているため
- **地図には効かせない。** Google マップは自前で 2 本指の操作を持っており（4.5.8）、`touch-action` を上書きすると壊れる。地図の要素は除く

### 6-3. 指 2 本の拡大を止める

`src/app/layout.tsx` の `viewport` に **`maximumScale: 1`** と **`userScalable: false`** を足す。

**副作用を承知のうえでの決定**（要件 4.5.12）。本文が 11〜13px で 503 か所あるため、見えにくいときに大きくする逃げ道が無くなる。文字の大きさそのものの見直しは提出後（9 章 未決定事項 No.16）。

## 成果物

- `src/app/globals.css`（入力欄の文字・`touch-action`）
- `src/app/layout.tsx`（`viewport`）
- テスト

## テスト要件

### 単体テスト
- `viewport` が `maximumScale: 1`・`userScalable: false` を持つこと
- `globals.css` に入力欄の 16px 指定と `touch-action: manipulation` があること（ファイルを読んで確かめる。`admin-actions.test.ts` がマイグレーションを読んでいるのと同じやり方）
- 地図の要素が `touch-action` の対象から外れていること

### 結合テスト
- 本番ビルドの HTML の `<meta name="viewport">` に `maximum-scale=1` と `user-scalable=no` が入ること

### E2Eテスト
- **実機で確かめる**（要件 8 章 92・93）。ホーム画面から開いた状態で、①入力欄を触っても拡大されない ②ダブルタップで拡大されない ③指 2 本で拡大されない ④**地図の 2 本指の拡大・縮小は今までどおり効く**

## 関連する受入条件

- 入力欄にカーソルを置いても画面が勝手に拡大されないこと
- ダブルタップでも指 2 本でも画面が拡大されないこと。ただし地図の 2 本指の拡大・縮小は効くこと
