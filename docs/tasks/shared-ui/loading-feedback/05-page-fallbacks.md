## 背景

`loading.tsx` は 2026-09-22 の性能改善で 10 ルートに入れたが、そこで線を引いた「主要な動線」から**必ず通る画面が漏れていた**。規約の再同意は全員が通り、新規登録は新しい人が必ず通る。要件 4.5.11 の表を 2026-09-30 に引き直したので、それに合わせる。

**`loading.tsx` が効かない条件に注意**（Next.js 16 の同梱ドキュメント `layout.js` の但し書き）。レイアウトが Cookie や未キャッシュの取得を行うと、レイアウトの描画が終わるまで `loading.tsx` は出ない。このプロジェクトのルートレイアウトは `getClaims()`（手元の署名検証。DB に触らない）だけなので問題ないが、**新しくレイアウトに問い合わせを足すときは同じ罠がある**。

## 実装内容

8 枚を追加する。どれも `src/components/skeleton/Skeletons.tsx` の部品を使い、**その画面の形**に合わせる。

| ルート | 何を待っている | 骨組みの形 |
|---|---|---|
| `/consent/renew` | 並列 2 本 → 未同意の種類ごとに直列（本文の全文） | 見出し＋カード 1〜2 枚 |
| `/account/status` | 並列 3 本 | 見出し＋カード 3 枚 |
| `/account` | 直列 2〜3 本 | 見出し＋行の並び |
| `/signup` | 認証サーバーへの往復 ＋ DB 1 本 | ロゴ＋カード |
| `/posts/new` | 下書きを開くときは直列 3 往復（署名 URL 込み） | 上 1/3 の地図の枠＋フォームの枠 |
| `/badges` | DB 1 本 | 見出し＋格子 |
| `/invitations/[token]` | 直列 2 本 | カード 1 枚 |
| `/itinerary-invitations/[token]` | 直列 2 本 | カード 1 枚 |

**置かない画面**（要件 4.5.11 の表）: ホーム・地図・あしあと・通報・スポットの写真一覧。待ちがほぼ無く、置くと一瞬ちらつくため。**管理画面も置かない**（保留。9 章 No.14）。

## 成果物

- 上の 8 つの `loading.tsx`
- 骨組みの部品が足りなければ `Skeletons.tsx` に足す（同じ形を 2 か所に書かない）

- 既存の骨組みの部品を使っていること（同じ形の写しを作っていないこと）

### 結合テスト
- なし

### E2Eテスト
- 実機で、要件 4.5.11 の表で「置く」としたページに移るとき骨組みが出ること（要件 8 章 91）。**先読みを切っているリンク**（通知一覧など）から入ったときに特に効く

## 関連する受入条件
