## 実装内容

### 4-1. スポット候補を押したときの登録（`src/components/spots/SpotAutocompleteInput.tsx`）

**ここだけ実害がある。** `handleSelectCandidate` は `POST /api/spots` を呼ぶが、`disabled` も表示も無いので、**続けて押すと同じスポットが二重に登録されうる**。

- 登録中を持ち、候補の一覧全体を押せなくする
- 押した候補には「登録しています…」を出す
- サーバーは 50m 以内の既存を 409 で返すので二重登録は起きにくいが、**同時に 2 本走ると両方が「既存なし」と判定しうる**ので、画面側で止める

### 4-2. 近くのコエの移動手段の切替（`src/components/map/NearbyVoices.tsx`）

取得中に前の結果を消していないため、徒歩から車に変えても古いカードと古い分数が残る。**切り替えた時点で前の結果を捨て**、初回と同じ「読み込んでいます…」を出す。

### 4-3. ホームの行き先の自由入力（`src/components/search/SearchTopScreen.tsx`）

入力欄を `disabled` にするだけ。地名の座標化（サーバー経由の外部 API）を待つので体感が長い。**「探しています…」を出す**。

### 4-4. 地図のピン取得・しおりの地図表示（`src/components/map/MapScreen.tsx`・`ItineraryMapOverlay.tsx`）

無言で遅れて出るため、空の地図が「投稿ゼロ」に見える。あしあとの地図（Task 2）と同じ形にする。**「どの条件で取り終えたか」を覚えて今の条件と見比べる**方式にし、取得中は「読み込んでいます…」を出す。

### 4-5. 投稿画面のスポット照合（`src/components/posts/PostComposeScreen.tsx`）

地図を動かすと 300ms 後に近くのスポットを照合し、スポット名が無言で変わる。**照合中はスポット名の欄に「近くのスポットを探しています…」を出す**。

### 4-6. 新規登録の「やめる」（`src/components/auth/SignupConsentScreen.tsx`）

`busy` で `disabled` にはなるが文言が変わらない。同じ画面の「登録しています…」と扱いが違う。**「やめています…」に変える**。

### 4-7. しおりのダイアログ 3 つ

`PeriodDialog.tsx`（期間の保存）・`MembersDialog.tsx`（メンバー削除・退出）・`InviteDialog.tsx`（招待リンクの発行・無効化）。いずれも `disabled` だけで文言が固定。**押したボタンの文言を「〜中…」に変える**。

### 4-8. アルバムの各操作（`src/components/albums/AlbumScreen.tsx`）

招待リンクの発行だけ「発行中…」が出て、名前変更・権限変更・メンバー削除・退出は `disabled` だけ。`run(key, …)` が既に「どの操作か」を持っているので、**その key を使って文言を出し分ける**。

### 4-9. 入力欄の候補取得 3 つ

`SpotAutocompleteInput`（スポット名）・`search/DestinationInput.tsx`（行き先）・`trips/TripTitleInput.tsx`（アルバム名）。候補が無言で遅れて出る。**招待のユーザー名検索（Task 2）と同じ形**にし、「探しています…」を出して、探し終わるまで「見つかりませんでした」を出さない。

## テスト要件

### 単体テスト
- スポット候補: 登録中は候補を押せず、押した候補に文言が出ること。**登録の API が 1 回しか呼ばれないこと**
- 近くのコエ: 移動手段を変えた直後に古いカードが消え、読み込み表示になること
- 地図 2 つ: 取得中は「読み込んでいます…」で、取り終えて 0 件のときだけ空の案内を出すこと（Task 2 と同じ）
- しおりのダイアログ・アルバム・新規登録の「やめる」: 押した直後に文言が変わること
- 入力欄 3 つ: 探している間は「見つかりませんでした」を出さないこと。入力を変えたら前の語の結果を残さないこと
