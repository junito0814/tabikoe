# Task 2: 読み込み中に「ありません」と言わない

## 依存

なし

## 背景

これは待ち表示の不足ではなく、**事実と違うことを画面が言っている**問題。見た人は機能が壊れていると判断する。2 か所ある。

| 場所 | 今の条件 | 何が起きるか |
|---|---|---|
| `src/components/map/MyMapScreen.tsx` | 表示範囲が決まっていて、取得に失敗しておらず、ピンが 0 件なら「この範囲に表示できるスポットはありません」 | **取得している最中もピンは 0 件**なので、記録があるのに「ありません」と出る |
| `src/components/invitations/InAppInvitePanel.tsx` | ユーザー名の検索結果が 0 件なら「見つかりませんでした」 | 入力してから結果が返るまでの間、必ず「見つかりませんでした」と出る |

## 実装内容

どちらも**「取得が終わったかどうか」を持ち、終わってからでないと空の案内を出さない**ようにする。

1. `MyMapScreen`
   - ピンの取得中を表す状態を持つ
   - 空の案内の条件に「取得が終わっている」を加える
   - 取得中は、空の案内の代わりに「読み込んでいます…」を出す（4.5.11 の場面 4）
2. `InAppInvitePanel`
   - ユーザー名検索の取得中を表す状態を持つ
   - 「見つかりませんでした」の条件に「取得が終わっている」を加える
   - 取得中は「探しています…」を出す

**デバウンスの待ち時間も「取得中」に含める。** 入力してから 300ms のデバウンスが明けるまでの間に古い結果が残っていると、やはり事実と違う（前の語の結果が出たまま）。入力が変わった時点で取得中にする。

## 成果物

- 各テスト

## テスト要件

### 単体テスト
- `MyMapScreen`: 取得中は「この範囲に表示できるスポットはありません」を出さず「読み込んでいます…」を出すこと。取得が終わって 0 件なら空の案内を出すこと。取得に失敗したときは今までどおりエラー表示になること
- `InAppInvitePanel`: 入力した直後（デバウンス中）と取得中は「見つかりませんでした」を出さないこと。取得が終わって 0 件なら出すこと
- 入力を変えたとき、前の語の結果が残らないこと

### 結合テスト
- なし（画面の状態だけで完結する）

### E2Eテスト
- 実機で、あしあとの地図を開いた直後に「ありません」が出ないこと（要件 8 章 86）

## 関連する受入条件

- 待っている間に「〜がありません」「見つかりませんでした」が出ないこと
