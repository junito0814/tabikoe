**Task 4・5 は 2026-09-30 に追加した。** 当初は提出までの時間を考えて Task 3 までに絞ったが、「UX をよくしたい」という方針を受けて**利用者が触れる箇所を全部**に広げた。Task 4 のうち**スポット候補の二重登録だけは実害がある**ので、4 の中で最初に入れる。

各タスクファイルは「依存」「実装内容」「成果物」「テスト要件（単体／結合／E2E）」「関連する受入条件」の構成で統一している（[rule.md](../../../rule.md)のテストルール区分に準拠）。

**Task 10 は 2026-10-02 に追加した。** Task 1 で入れたはずの「起動直後の青」が 2 回とも効かず、3 回目に原因を突き止めたため（要件 4.5.11 の「場面 1 の決着」）。**起動が遅いこと自体は別の話**で、[performance Task 4（温める）](../performance/04-keep-warm.md) で扱う。

**Task 7〜9 は 2026-09-30 に追加した。** 7 は React の仕組みを使わない CSS だけの話で、8 とは別物（時間あたりの効きがいちばん大きいので先に入れる）。8 は**まず 30 分で実機で動くかを見極め**、動かなければ閉じる。**5 と 8 は同じ `loading.tsx` を触るので、まとめて書くと 8 ファイルを 2 回触らずに済む**。9 は単独アプリにしたことで「最新にする手段が無くなった」穴を塞ぐもの。
