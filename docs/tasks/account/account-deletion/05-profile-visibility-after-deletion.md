# Task 5: 退会後のプロフィール非表示処理

> 出典: [account-deletion.md](../../../user-stories/account/account-deletion.md)
> インデックス: [account-deletion](00-index.md)

## 依存

- [Task 1: 退会実行 Route Handler（ユーザー匿名化・関連データ削除）](01-deactivation-handler.md)
- F-AC-03 [ログアウト Route Handler（/api/auth/logout）](../logout/01-logout-route-handler.md)（セッション無効化ロジックの再利用）

## 実装内容

- `is_deleted=true`のユーザーのプロフィール画面へのアクセスを非表示（404等）とする
- 退会したユーザー自身のセッションは、退会処理完了と同時に無効化し、未ログイン状態に戻す（F-AC-03のログアウト処理を再利用）

## 成果物

- プロフィール取得処理への`is_deleted`チェックの組み込み
- 退会処理完了時のセッション無効化呼び出し

## テスト要件

### 単体テスト
- `is_deleted=true`のユーザーIDに対するプロフィール取得処理が「非表示」を示す結果（404相当）を返すことを検証する

### 結合テスト
- テスト用DBで`is_deleted=true`のユーザーのプロフィールURLにアクセスし、404等の非表示応答が返ることを確認する
- 退会したユーザーが退会直後に別画面へアクセスすると、未ログイン状態として扱われることを確認する

### E2Eテスト
- 退会直後にプロフィール画面へアクセスし、非表示（404等）になることを確認する

## 関連する受入条件

- 退会後、プロフィール画面が非表示になること
