# Task 3: 管理者退会時の引き継ぎ確認フロー

> 出典: [account-deletion.md](../../../user-stories/account/account-deletion.md)
> インデックス: [account-deletion](00-index.md)

## 依存

- [Task 1: 退会実行 Route Handler（ユーザー匿名化・関連データ削除）](01-deactivation-handler.md)

## 実装内容

- 退会しようとしているユーザーの`users.is_admin`が`true`の場合、退会実行APIの呼び出し前に「他の管理者へ`is_admin`フラグの引き継ぎを完了した」旨の明示的な確認（チェックボックス等）を必須とする
- 確認が行われていない場合、退会処理（Task1）を実行させない
- 運用手順の詳細（誰が・いつ引き継ぐか）は要件定義書9章の未決定事項であるため、本タスクでは「確認を必須にするUI・APIバリデーション」のみを実装範囲とする

## 成果物

- 管理者退会確認バリデーション（Route Handler側）

## テスト要件

### 単体テスト
- `is_admin=true`のユーザーが確認フラグなしで退会APIを呼び出した場合、処理が拒否されることを検証する
- `is_admin=false`のユーザーは確認フラグなしでも通常通り退会できることを検証する

### 結合テスト
- テスト用DBで`is_admin=true`のユーザーに対し、確認フラグありのリクエストで退会処理（Task1）が実行されることを確認する
- 確認フラグなしのリクエストでは`users`テーブルに変更が発生しないことを確認する

### E2Eテスト
- なし（[Task 6: 受入テスト（E2E）](06-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- 管理者アカウントの退会時、他の管理者への引き継ぎ確認が必須となること
