# Task 2: アクセストークンの自動リフレッシュ処理

> 出典: [session-management.md](../../../user-stories/account/session-management.md)
> インデックス: [session-management](00-index.md)

## 依存

- [Task 1: セッション検証Middlewareの実装](01-session-verification-middleware.md)

## 実装内容

- Middleware／Route Handlersでアクセストークンの有効期限切れを検知した場合、保持しているリフレッシュトークンを用いてSupabase Authに対しトークン再発行をリクエストする
- 再発行に成功した場合、新しいアクセストークン・リフレッシュトークンをレスポンスのCookieに再設定する（Supabaseはリフレッシュトークンローテーションを行うため、都度更新が必要）
- リフレッシュ処理はユーザーの画面操作を中断せず、透過的に行われるようにする

## 成果物

- トークン自動リフレッシュ処理（共通関数）

## テスト要件

### 単体テスト
- 期限切れのアクセストークンと有効なリフレッシュトークンを入力とした場合、リフレッシュAPI（モック）が呼び出され、新トークンでCookieが更新されることを検証する
- リフレッシュAPIがエラーを返した場合（Supabase側障害等）、適切にエラーハンドリングされることを検証する

### 結合テスト
- テスト用Supabaseプロジェクトで期限切れのアクセストークンを用意し、実際のリフレッシュフローが成功して新しいセッションが確立されることを確認する

### E2Eテスト
- テスト環境でアクセストークンの有効期限を短縮した状態で画面操作を行い、期限切れをまたいでもユーザーにエラーが表示されず操作が継続できることを確認する

## 関連する受入条件

- アクセストークンの有効期限切れ時、画面操作を中断せず自動的に再取得されること
