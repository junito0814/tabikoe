# Task 7: アカウント新規作成画面（SC-20）と同意フロー

> 出典: [signup-login.md](../../../user-stories/account/signup-login.md)
> インデックス: [signup-login](00-index.md)

## 依存

- [Task 4: OAuthコールバック Route Handler（/api/auth/callback）](04-oauth-callback-handler.md)
- [Task 5: 初回ログイン時のユーザーレコード作成ロジック](05-initial-user-record-creation.md)

## 実装内容

- 同意画面（SC-20）を実装する。**利用規約・個人情報保護方針の 2 つの同意チェックボックス**（2026-09-22 に 1 つから分割）と「同意してはじめる」「やめる」を配置する。両方にチェックするまでボタンは押せない。Google のボタンと SC-01 への導線は置かない（[Task 11](11-google-once-signup.md) で作り直し）
- 両方に同意した場合のみアカウント作成処理（Task 5）に進む。どちらか一方でも同意が無ければ処理を中断する（`POST /api/auth/signup` に `terms`・`privacy` を渡し、サーバー側で両方を確認する。Task 11）
- 作成が終わったらログイン画面を挟まず、ログイン後の着地点（SC-00）へそのまま遷移する
- 同意日時を`users.consented_at`に記録する。既にアカウントがある場合は上書きしない（初回サインアップ時の値を保持する）
- **アカウントが無い状態でログイン画面（SC-01）から認証を通った場合**は、同意を得ていないためアカウントを作成せず、~~確立されたセッションを破棄した上で~~ セッションは保持したまま SC-20 へ誘導する（2026-09-22。Task 11）
  - どちらの画面から来てもIdP認証のフローは同一のため、アカウントの有無はコールバック（Task 4）側で判定する必要がある
- 同意チェックボックスはキーボードのみで操作できるようにする（7.7 アクセシビリティ準拠）。`role="checkbox"`を付けた`<span>`等ではなく、フォーカス可能な実体のあるチェックボックスとして実装する
  - 同意はログインの必須条件のため、ここがキーボード操作できないとキーボードユーザーはログイン自体ができなくなる

## 成果物

- `SC-20`アカウント新規作成画面コンポーネント
- 同意チェックのサーバー側バリデーション
- コールバックにおけるアカウント有無の判定と、未登録ユーザーのSC-20への誘導

## テスト要件

### 単体テスト
- チェックボックスが未チェックの状態では「アカウントを作成」ボタンが無効化される、またはサーバー側送信をブロックすることを検証する
- 同意チェックボックスがキーボード（Tabでのフォーカス移動・Spaceでのトグル）で操作できることを検証する
- サーバー側で同意フラグ（利用規約・個人情報保護方針のどちらか）が`false`または未送信のリクエストを受け取った場合、ユーザー作成処理を実行せずエラーを返すことを検証する
- 画面で 2 つのチェックのうち片方だけでは「アカウントを作成」が押せず、両方で押せることを検証する

### 結合テスト
- テスト用DBに対し、同意ありのリクエストで`users`テーブルが作成され`consented_at`が記録されること、同意なしのリクエストでは何も作成されないことを確認する
- 既にアカウントがあるユーザーがSC-20から操作した場合、`consented_at`が上書きされないことを確認する
- アカウントが無い状態でログイン画面から認証を通った場合、`users`にレコードが作成されず、セッションも破棄されることを確認する

### E2Eテスト
- SC-20で同意せずに離脱した場合はアカウントが作成されず、再度SC-20を開いても同意欄が表示されることを確認する
- 同意して続けた場合、通常のログイン完了後の画面に遷移することを確認する
- アカウントが無い状態でSC-01からログインを試み、SC-20へ誘導されることを確認する

## 関連する受入条件

- 同意せずにサインアップ操作を行った場合、アカウントが作成されないこと
- アカウント新規作成画面にのみ同意欄（2 つのチェック）が表示され、ログイン画面には表示されないこと。SC-20 から SC-01 へ遷移でき、SC-01 に SC-20 への導線が無いこと
- アカウントが無い状態でログイン画面から認証を通った場合、アカウントが作成されず、アカウント新規作成画面へ誘導されること
