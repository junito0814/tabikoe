## 依存

- [Task 1: Supabase Auth OAuthプロバイダ設定](01-oauth-provider-setup.md)

## 実装内容

- Googleのログインボタンを配置する。**同意欄は置かない**（同意取得はアカウント新規作成画面（SC-20）の責務。[Task 7](07-consent-flow.md)参照）
- ボタン押下でSupabase Authの`signInWithOAuth`を呼び出す
- ~~「アカウントをお持ちでない方」としてSC-20への導線を置く~~ → 2026-09-22 に廃止。SC-01 に SC-20 への導線は置かない（未登録者はコールバックで自動的に SC-20 へ誘導される。[Task 7](07-consent-flow.md)）
- 未ログインで他画面から誘導されてきた場合、元の遷移先を保持し、ログイン後に復帰できるようにする（`redirect_to`パラメータ等）

## 成果物

- `SC-01`ログイン画面コンポーネント

## テスト要件

### 単体テスト
- ログインボタンが表示されることを検証するレンダリングテスト
- **同意欄（利用規約・個人情報保護方針のチェックボックス）が表示されないことを検証するテスト**
- ボタン押下時に、`google`を引数として`signInWithOAuth`（モック）が呼び出されることを検証するテスト
- URLクエリに`redirect_to`が含まれる場合、その値がボタン押下時のOAuthリクエストパラメータに引き継がれることを検証するテスト

### 結合テスト
- Supabase Authクライアント（テスト用プロジェクト）に対して実際に`signInWithOAuth`を呼び出し、想定した認可URLへのリダイレクトが発生することを確認する

### E2Eテスト
- 未ログイン状態でログイン必須画面（例：SC-02）に直接アクセスすると、ログイン画面（SC-01）へリダイレクトされ、`redirect_to`が保持されていることを確認する
- ログイン画面でログインボタンをクリックすると、Googleの認可画面へ遷移することを確認する

## 関連する受入条件

- 未ログイン状態でトップページ以外の画面にアクセスすると、ログイン画面へ誘導されること（3.5.4参照）
