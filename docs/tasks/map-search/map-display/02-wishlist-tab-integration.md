# Task 2: 「行きたい」タブ用ピン取得ロジック

> 出典: [map-display.md](../../../user-stories/map-search/map-display.md)
> インデックス: [map-display](00-index.md)

## 依存

- records/wishlist（「行きたい」保存機能。カテゴリ「records」で作成予定）

## 実装内容

- 「行きたい」タブ選択時、ログインユーザー自身が「行きたい」保存したスポットのみをピンとして取得するロジックを実装する
- Task1の`/api/spots`にタブ種別（`view=all|wishlist`）のパラメータを追加するか、専用エンドポイントとするかは実装時に決定する
- 取得件数は最大100件に制限する（Task1と同一の制約）

## 成果物

- 「行きたい」タブ用のピン取得処理（Task1のRoute Handler拡張、または専用エンドポイント）

## テスト要件

### 単体テスト
- ログインユーザー自身の「行きたい」保存スポットのみが対象となり、他ユーザーの保存分が含まれないことを検証する

### 結合テスト
- テスト用DBで、複数ユーザーの「行きたい」保存データが混在する状態から、リクエストしたユーザー自身の保存分のみが返ることを確認する

### E2Eテスト
- なし（[Task 6: 受入テスト（E2E）](06-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- 全体マップで「全体」「行きたい」タブが排他的に切り替わること
