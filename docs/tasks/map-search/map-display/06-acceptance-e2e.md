## 実装内容

- 本ストーリーの受入条件をすべて検証する
- 投稿100件程度のデータを用いた表示速度の確認を含む

## 成果物

- E2Eテストシナリオ（手動 or 自動、Playwright等）
- 検証結果の記録

## テスト要件

### 単体テスト
- 対象外（本タスクはE2E検証が主目的）

### 結合テスト
- 対象外（Task 1〜5で実施済み）

### E2Eテスト
以下のシナリオを実施する。

1. ログイン後、位置情報を許可した状態でSC-02にアクセスし、現在地が初期表示されることを確認する
2. 位置情報を拒否した状態でSC-02にアクセスし、東京駅周辺が初期表示されることを確認する
3. 「全体」「行きたい」タブを切り替え、表示されるピンが排他的に切り替わることを確認する
4. 自分の投稿があり「行きたい」保存もしているスポットが、「全体」タブ上で通常ピンとして表示されることを確認する
5. 投稿100件程度が存在するエリアを表示し、3秒以内に描画が完了することを確認する
6. Google Maps JavaScript APIの読み込みを失敗させ、「地図を読み込めませんでした」と表示されることを確認する

## 関連する受入条件

- 地図上に現在地が表示され、位置情報が拒否された場合は東京駅周辺が初期表示されること
- 全体マップで「全体」「行きたい」タブが排他的に切り替わること
- 同一スポットへの複数投稿が1ピンに集約されること
- ピンの区別が色のみに依存せず、形状・アイコンでも判別できること
- 自分の投稿があり同時に「行きたい」保存もしているスポットが、「全体」タブ上で通常ピンとして表示されること
- 表示中の地図範囲内のピンが最大100件まで読み込まれること
- マップ画面が、投稿100件程度の条件下で3秒以内に表示されること
