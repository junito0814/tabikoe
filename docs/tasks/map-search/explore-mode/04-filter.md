## 依存

Task 1（近くの投稿 API）・Task 2（探すモード UI）

## 背景

探すモードは移動手段で**半径**は変えられるが、**何を探しているか**は指定できない。「いま出先で、ちょうどいい場所を探している人」には足りない（2026-10-02 の相談）。

投稿一覧（3.4.2）には既に絞り込みがあるので、同じものを地図にも置く。

## ここが設計の肝

**ピンとカードの両方に効かせる。** 地図は 2 つの別々の場所からデータを取っている。

| | 取得元 | いまの条件 |
|---|---|---|
| 地図のピン | `getMapPins` ← `/api/map/pins` | 表示範囲だけ |
| 下のカード | `getNearbyPosts` ← `/api/posts/nearby` | 現在地＋移動手段だけ |

**片方だけ直すと食い違って壊れて見える**（地図に出ているピンが、下のカードに無い）。

**ピンの数字も絞り込んだ結果にする。** 「3 件」と出ているのに開いたら 1 件では困るので、**投稿件数・評価の平均・カテゴリ（ピンの色）も、条件に合う投稿だけから計算する**。

`getMapPins` は `spots` から `posts!inner(...)` を埋め込んで取り、**埋め込んだ投稿の配列から集計している**。埋め込み側に条件を足せば、集計は自動的に絞り込み後になる。

## 実装内容

### 4-0. 作りの方針（2026-10-02 に決まったこと）

**投稿を 1 件ずつ絞るのではなく、スポットの代表値で絞る。** 地図が探しているのは**場所**なので、「誰かが 1 回だけ 3,000 円で済んだ店」ではなく「**だいたい 3,000 円の店**」が出るようにする。

| 条件 | 代表値 | 既にあるもの |
|---|---|---|
| カテゴリ | いちばん多いもの。同数なら新しい方 | **`resolveSpotCategory`**（`src/lib/map/spot-category.ts`） |
| 滞在時間 | 同上 | 無い（同じ形で書く） |
| 予算 | 平均 | 無い |
| 評価 | 平均 | **`averageRating`**（`get-map-pins.ts`） |

**この結果、クエリに条件を足すだけでは済まない。** 集めてから集計し、そのあとで絞る。

```
投稿を集める → スポットごとに代表値を出す → 代表値で絞る → ピンとカードを作る
```

**`applyFilters`（`search-posts.ts`）は使わない。** あれは投稿 1 件ずつの絞り込みで、今回の作りとは別物。ただし**判断の部品**（`costRangeBounds`・`durationsMatching`）は流用する。

### 4-1. 代表値と判定（`src/lib/map/spot-aggregate.ts`。新規・純粋関数）

| 関数 | すること |
|---|---|
| `resolveSpotDuration(posts)` | 滞在時間の代表（`resolveSpotCategory` と同じ考え方） |
| `averageCost(posts)` | 予算の平均。**未入力は数えない**。全部未入力なら `null` |
| `matchesSpotFilters(aggregate, filters)` | 代表値が条件に合うかを返す |

**決めごと**

- **未入力の投稿は数えない。** 全部未入力のスポットは、その条件で絞ると落ちる（投稿一覧の予算の絞り込みと同じ扱い）
- **「以上」は同じ値を含む。** 評価の平均は小数 1 桁なので、「★4 以上」は 4.0 ちょうどを含む
- **カテゴリは `resolveSpotCategory` をそのまま使う。** 別に書くと、**カテゴリで絞ったのに違う色のピンが残る**（ピンの色を決めているのが同じ関数のため）

### 4-2. 代表値を出す場所は 1 か所（`src/lib/map/get-map-pins.ts`）

**ピンの側で計算し、カードはその結果を使う。**

カードの側（`getNearbyPosts`）は取得に上限（`NEARBY_FETCH_CAP = 200`）があり、**投稿の多い場所ではスポットの投稿が途中までしか取れない**。別々に計算すると、同じスポットなのに**ピンとカードで判定が食い違う**。

`getMapPins` の集計に `cost`・`duration` を足し、代表値を返すようにする。絞り込みはそのあと。

**ピンの数字も絞り込み後にする** ── `postCount`・`ratingAverage`・`category` は、条件に合うスポットについて**そのスポットの全公開投稿**から出す（投稿を間引くのではなく、スポットごと落とす作りなので自然にそうなる）。

### 4-3. カード（`src/lib/posts/nearby-posts.ts`）

**条件に合うスポットの id の集合**を受け取り、それ以外のスポットの投稿を落とす。代表値の計算はしない（4-2 の結果を使う）。

### 4-4. API（`src/app/api/map/pins/route.ts`・`src/app/api/posts/nearby/route.ts`）

絞り込みの条件をクエリから受け取る。名前は投稿一覧と揃える。

### 4-5. 画面（`src/components/map/NearbyVoices.tsx`・`MapScreen.tsx`・`FilterSheet.tsx`）

```
近くのスポット                    [徒歩 ⌄]   [≡]
```

- 移動手段の横の**「移動手段」の文字を外す**（`aria-label` は残す）
- その右に**絵だけの絞り込みボタン**。効いているときは色を変え、**効いている条件の数**を付ける
- `FilterSheet` に**出し分けの引数**を足す（距離を出さない／期間を出さない／評価とチェックボックスを出す）
- 「タビコエだけの場所」は**チェックボックスの行**として足す。文言は 1 行だけ
- 見出しは「**予算（平均）**」「**評価（平均）**」

**0 件のときの文言を出し分ける。** 絞り込みが効いているときは「**条件に合う場所がありません**」、効いていないときは今までどおり「この範囲に投稿はありません」。

### 4-6. 状態の保存（`src/lib/map/map-state.ts`）

絞り込みの条件を URL と地図の状態に保存し、戻ってきたときに同じ条件で開く（3.4.3 の復元の一部）。

## テスト要件

### 単体テスト
- `resolveSpotDuration`: いちばん多い滞在時間を返すこと。同数なら新しい方
- `averageCost`: **未入力を数えないこと**。全部未入力なら `null`
- `matchesSpotFilters`:
  - 平均 3.5（★5 が 1 件・★2 が 1 件）のスポットが「★4 以上」に**残らない**こと
  - 「★4 以上」が **4.0 ちょうどを含む**こと
  - 予算が全部未入力のスポットが、予算で絞ると落ちること
  - カテゴリの判定が `resolveSpotCategory` と**同じ答え**になること（ピンの色と食い違わない）
- ピンの集計: 条件に合うスポットの `postCount`・`ratingAverage`・`category` が**そのスポットの全公開投稿**から出ること
- カード: 条件に合うスポットの投稿だけ残ること
- 画面: 絞り込みが効いているときボタンの色と数が変わること。距離と期間が出ないこと
- **0 件の文言**: 絞り込みが効いていれば「条件に合う場所がありません」、効いていなければ「この範囲に投稿はありません」
- 状態の保存: 条件が URL と地図の状態に入り、復元されること

### 結合テスト
- なし（サーバーのクエリは単体テストで条件の組み立てを確かめる）

### E2Eテスト
- **実機で確かめる**（要件 8 章 100）。①絞り込むとピンとカードの**両方**が減る ②ピンの件数が絞り込み後の数になる ③投稿一覧へ行って戻ると同じ条件で開く
