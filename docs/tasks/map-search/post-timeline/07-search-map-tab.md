# Task 7: 検索結果に「地図」タブを足す

> 出典: [post-timeline.md](../../../user-stories/map-search/post-timeline.md)
> インデックス: [post-timeline](00-index.md)
> 要件定義書 3.4.2「投稿／写真／地図の切替」「地図タブ」、ワイヤーフレーム決定事項 71

## 依存

Task 2（タイムライン UI）、explore-mode Task 2（探すモード UI。見せ方を流用する）

## 背景

「どこへ行く？」で検索した結果が**縦一覧だけ**で、どこにあるのかが分からない（2026-10-04 のメンタリング 8）。

**上 1/3 地図は採らない。** 検索結果は 20 件ずつスクロールして読む画面で、常に 1/3 を地図に取られると読みにくい（スポット別は 1 スポットぶんなので上 1/3 でよい）。

## ここが設計の肝

**探すモード（3.4.6）と同じ形を使い回す。** 地図を全面に出し、下に横スクロールのカードを並べる形は**既に出来上がっている**（`MapScreen` の explore モード＋`NearbyVoices`）。同じ見た目を 2 つ作らない（約束 14）。

違いは「どのスポットを出すか」だけ。

| | 探すモード | 検索結果の地図タブ |
|---|---|---|
| 出すスポット | 現在地から半径内 | **検索結果のスポット**（読み込み済みのぶん） |
| 中心 | 現在地 | **結果が全部入る範囲**（最初の 1 回だけ） |
| カードの並び | 近い順 | **一覧と同じ並び替え** |

## 実装内容

### 7-1. 切替に 3 つ目を足す（`ViewToggle`・`list-view.ts`）

`ListView` に `map` を足す。URL は写真タブと同じく `view=map`（戻ってきたら地図のまま開く）。

**検索結果のときだけ**出す。スポット別の投稿一覧には出さない（そのスポットは決まっているため）。

### 7-2. 地図の中身（`SpotSearchScreen` から使う）

- ピンは**読み込み済みの結果のスポット**。続きを読めばピンも増える
- 開いたときに**全部入る範囲**へ合わせる（`fitBounds`）。**追加の通信はしない**（カードが持っている緯度経度を使う）
- **以降は動かさない。** 続きを読んでも地図は動かさない（見ている場所が飛ばないため）。利用者の操作（ドラッグ・拡大縮小）は Google マップのまま
- **カードを選ぶとそのピンが強調されて地図が寄る**（探すモードと同じ）
- カードを右端まで送ったら次の 20 件を読む

### 7-3. 絞り込みから「距離」を外す

地図タブが付くと基準点が 2 つ（検索した場所と地図の中心）になり紛らわしい。地図を動かして見る形に置き換える（要件 3.4.2）。
