# Task 2: 削除対応時の通知連携

> 出典: [report-handling.md](../../../user-stories/admin/report-handling.md)
> インデックス: [report-handling](00-index.md)

## 依存

- [Task 1: 通報対応操作 Route Handler（非公開化／削除／問題なし）](01-report-action-handler.md)
- notifications/notification-triggers Task1: 通知作成の共通処理（`docs/tasks/notifications/notification-triggers/`、F-NT-01側で作成予定）

## 実装内容

- Task1の対応操作が「削除」の場合のみ、通知機能の共通通知作成処理を呼び出し、通報した本人へアプリ内通知を送る
- 「非公開化」「問題なし」の場合は通知を送らない
- 被通報者へは、いずれの対応の場合も通知を送らない（匿名性の担保のため）

## 成果物

- Task1のRoute Handlerから通知共通処理を呼び出す連携コード

## テスト要件

### 単体テスト
- 対応操作が「削除」の場合のみ通知作成処理が呼び出されることを検証する
- 「非公開化」「問題なし」の場合は通知作成処理が呼び出されないことを検証する
- 被通報者宛の通知が生成されないことを検証する

### 結合テスト
- テスト用DBで「削除」対応を実行し、通報者宛の`notifications`レコードが作成されることを確認する
- 「非公開化」「問題なし」対応では`notifications`レコードが作成されないことを確認する

### E2Eテスト
- なし（[Task 4: 受入テスト（E2E）](04-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- 「削除」で対応した対象が削除され、復元できないこと。この対応の場合のみ通報者へアプリ内通知が送られること
- 「問題なし」「非公開化」の場合は通報者へ通知が送られないこと。被通報者への通知はいずれの対応でも送られないこと
