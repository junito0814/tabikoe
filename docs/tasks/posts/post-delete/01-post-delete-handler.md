# Task 1: 投稿削除 Route Handler（カスケード削除）

> 出典: [post-delete.md](../../../user-stories/posts/post-delete.md)
> インデックス: [post-delete](00-index.md)

## 依存

- post-creation [投稿関連テーブルのスキーマ定義・マイグレーション](../post-creation/01-post-schema-migration.md)

## 実装内容

- `DELETE /api/posts/{id}`を実装する
- 投稿者本人のみ削除可能とする（共同アルバムのオーナーであっても他人の投稿は削除不可）
- 紐づくコメント・いいね・写真・動画（`post_photos`）レコードを同一トランザクション内で削除する
- 紐づく写真・動画の実体ファイルをSupabase Storageから削除する
- `trips`（旅行／アルバム）自体は削除しない

## 成果物

- `app/api/posts/[id]/route.ts`（DELETE）

## テスト要件

### 単体テスト
- 投稿者本人以外からの削除リクエストが拒否されることを検証する

### 結合テスト
- テスト用DBで実際に投稿を削除し、紐づくコメント・いいね・`post_photos`が同時に削除されることを確認する
- 紐づく写真・動画ファイルがStorageから削除されることを確認する
- 削除後も`trips`レコード自体は残存することを確認する
- トランザクションが途中で失敗した場合、全ての変更がロールバックされることを確認する

### E2Eテスト
- なし（[Task 5: 受入テスト（E2E）](05-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- 投稿者本人が投稿を削除できること（投稿者本人以外は削除できない）
- 削除に伴い、紐づくコメント・いいね・写真・動画が同時に削除されること
