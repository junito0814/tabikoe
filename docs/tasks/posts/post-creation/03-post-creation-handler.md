# Task 3: 投稿作成 Route Handler（バリデーション・保存）

> 出典: [post-creation.md](../../../user-stories/posts/post-creation.md)
> インデックス: [post-creation](00-index.md)

## 依存

- [Task 1: 投稿関連テーブルのスキーマ定義・マイグレーション](01-post-schema-migration.md)

## 実装内容

- `POST /api/posts`を実装する
- サーバー側で以下をバリデーションする
  - 必須項目（旅行タイトル・スポット名・カテゴリ・滞在時間・星評価・写真動画1点以上・公開設定）の存在
  - 費用が0〜999,999の整数であること
  - 星評価が1〜5の整数であること
  - 日付が未来日でないこと（JST基準）
  - 感想が4,000文字以内（書記素クラスタ単位）であること
- 認証済みユーザーのみ実行可能。`trip_id`・`spot_id`の存在を検証する

## 成果物

- `app/api/posts/route.ts`（POST）

## テスト要件

### 単体テスト
- 各バリデーションルール（費用範囲、星評価整数、日付未来不可、感想文字数）について、正常系・異常系それぞれを検証する
- 未ログイン状態でのリクエストが拒否されることを検証する

### 結合テスト
- テスト用DBに対して実際にINSERTが実行され、`posts`テーブルへ正しい値が保存されることを確認する
- 存在しない`trip_id`／`spot_id`を指定したリクエストが拒否されることを確認する
- 不正なリクエスト（必須項目欠落等）がエラーレスポンスを返すことを確認する

### E2Eテスト
- なし（[Task 6: 投稿作成フローの画面統合・受入テスト（E2E）](06-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- 必須項目を入力した投稿の作成ができ、費用が数値（1人あたり）で保存されること
