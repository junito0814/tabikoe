# Task 4: 写真・動画アップロード処理の統合（投稿作成時）

> 出典: [post-creation.md](../../../user-stories/posts/post-creation.md)
> インデックス: [post-creation](00-index.md)

> **2026-09-15 追記**: 動画（MP4）の半分は、Vercel の本文上限（4.5MB）のため写真と同じ経路では実装できず、[video-upload](../video-upload/00-index.md) として別ストーリーに切り出した。本タスクの成果物は写真の経路（`POST /api/posts/photos`）のみ。

## 依存

- [Task 3: 投稿作成 Route Handler（バリデーション・保存）](03-post-creation-handler.md)
- F-AC-04 [画像アップロード共通処理（EXIF除去・向き補正・縮小画像生成）の実装](../../account/profile-edit/03-image-upload-processing-common.md)

## 実装内容

- F-AC-04で実装した画像処理共通モジュール（EXIF除去・向き補正・縮小画像生成）を再利用し、投稿への写真アップロードを実装する
- 動画（MP4形式、1点あたり最大100MB、再生時間1分以内）について、ffmpegを用いて先頭フレームを抽出しサムネイル画像を生成する新規処理を実装する
- 動画のEXIF相当の位置情報メタデータも、サムネイル生成と同じ処理の中で除去する
- `post_photos`テーブルへ複数枚（枚数上限なし）を保存し、`display_order`を管理する
- `media_type`（`photo`／`video`）を判定して記録し、動画の場合は`duration_seconds`も保存する

## 成果物

- 投稿写真・動画アップロード処理（Route Handlers内）

## テスト要件

### 単体テスト
- ファイル形式（写真：JPEG／PNG、動画：MP4）・サイズ上限（写真10MB、動画100MB）の検証ロジックを検証する
- 動画の再生時間が1分を超える場合に拒否されることを検証する
- `media_type`の判定ロジック（拡張子・MIMEタイプに依存しすぎない実体ベースの判定）を検証する

### 結合テスト
- テスト用Supabase Storageへ実際に写真・動画（サムネイル含む）がアップロードされ、`post_photos`にレコードが作成されることを確認する
- 動画アップロード時、ffmpegによる先頭フレーム抽出が成功し、サムネイルURLが記録されることを確認する
- 複数枚（6点以上）添付時、`display_order`が入力順に正しく採番されることを確認する

### E2Eテスト
- なし（[Task 6: 投稿作成フローの画面統合・受入テスト（E2E）](06-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- 写真アップロード時、EXIF位置情報が除去され、向きが正しい縮小画像が生成されること
- 動画（MP4形式、100MBまで、1分以内）をアップロードでき、先頭フレームのサムネイルが自動生成されること
- 写真・動画をあわせて6点以上添付した投稿が正しく保存されること
