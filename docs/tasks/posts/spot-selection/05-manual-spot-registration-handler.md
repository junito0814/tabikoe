# Task 5: スポット手動登録 Route Handler（重複防止ロジック含む）

> 出典: [spot-selection.md](../../../user-stories/posts/spot-selection.md)
> インデックス: [spot-selection](00-index.md)

## 依存

- [Task 1: spots テーブルの近傍検索インデックス整備](01-spots-geo-search-index.md)

## 実装内容

- `POST /api/spots`を実装する
- 登録リクエストの緯度経度から半径50m以内に既存スポットがあるかをTask1の近傍検索を用いて判定する
- 既存スポットがある場合は登録を拒否し、既存スポットの情報を返す（クライアント側で選択を促す）
- 既存スポットがない場合、スポット名・緯度経度を`spots`テーブルに新規登録する（`source='manual'`）
- 登録されたスポットは以降、全ユーザーの検索候補（Task2）にも表示される

## 成果物

- `app/api/spots/route.ts`（POST）

## テスト要件

### 単体テスト
- 半径50m判定の境界値（49m：拒否、51m：許可）を検証する
- スポット名が未入力の場合に拒否されることを検証する

### 結合テスト
- テスト用DBに対し、重複なしのリクエストで新規`spots`レコードが作成されることを確認する
- 50m以内に既存スポットがあるリクエストで、登録が行われず既存スポット情報が返ることを確認する
- 手動登録したスポットが、Task2の候補検索APIから取得できることを確認する

### E2Eテスト
- なし（[Task 7: 受入テスト（E2E）](07-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- 候補にないスポットの手動登録ができること
- 半径50m以内に既存スポットがある場合、登録が拒否され既存スポットの選択が促されること
- 手動登録したスポットが以降の他ユーザーの検索候補にも表示されること
