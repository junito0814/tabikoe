# Task 3: 投稿編集画面UI（SC-03 編集モード）

> 出典: [post-edit.md](../../../user-stories/posts/post-edit.md)
> インデックス: [post-edit](00-index.md)

## 依存

- [Task 1: 投稿編集 Route Handler（PATCH /api/posts/{id}）](01-post-edit-handler.md)
- [Task 2: 写真・動画の個別編集（追加・削除）ロジック](02-media-edit-logic.md)

## 実装内容

- SC-03（投稿作成画面）を編集モードとして再利用し、既存の投稿データを初期値として表示する
- 各フィールドを編集可能にし、保存ボタン押下でTask1のAPIを呼び出す
- 写真・動画の一覧に削除ボタンを設け、追加ボタンから新規ファイルを選択できるようにする
- 投稿者本人以外がアクセスした場合、編集不可であることを明示する（編集モードへの遷移自体をブロックする）

## 成果物

- SC-03編集モードのUI実装

## テスト要件

### 単体テスト
- 既存投稿データがフォームの初期値として正しく反映されることを検証する
- 写真・動画の削除ボタン押下でTask2のAPI（モック）が呼び出されることを検証する
- 投稿者本人以外のユーザーが編集画面にアクセスした場合、編集操作ができない状態になることを検証する

### 結合テスト
- 実際のAPIと連携し、フォーム編集後の保存が反映されることを確認する

### E2Eテスト
- なし（[Task 4: 受入テスト（E2E）](04-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- 投稿の全項目を編集できること
- 写真・動画を個別に削除・追加でき、枚数上限がないこと
