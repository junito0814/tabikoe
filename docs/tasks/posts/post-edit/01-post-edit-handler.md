# Task 1: 投稿編集 Route Handler（PATCH /api/posts/{id}）

> 出典: [post-edit.md](../../../user-stories/posts/post-edit.md)
> インデックス: [post-edit](00-index.md)

## 依存

- post-creation [投稿作成 Route Handler（バリデーション・保存）](../post-creation/03-post-creation-handler.md)

## 実装内容

- `PATCH /api/posts/{id}`を実装する
- 投稿作成時（F-PO-01）と同じバリデーションルールを、変更対象フィールドに適用する
- 投稿者本人のみ編集可能とする（共同アルバムのオーナーであっても他人の投稿は編集不可）
- 編集操作では`posts.created_at`（投稿日時・新着順の基準）を更新しない

## 成果物

- `app/api/posts/[id]/route.ts`（PATCH）

## テスト要件

### 単体テスト
- 投稿者本人以外からの編集リクエストが拒否されることを検証する
- 編集リクエストの前後で`created_at`が変化しないロジックであることを検証する
- 各フィールドのバリデーション（費用範囲、星評価整数等）が編集時にも適用されることを検証する

### 結合テスト
- テスト用DBで実際に更新を行い、`posts`テーブルの該当フィールドのみが更新され`created_at`が不変であることを確認する
- 共同アルバムのオーナーが他メンバーの投稿を編集しようとした場合に拒否されることを確認する

### E2Eテスト
- なし（[Task 4: 受入テスト（E2E）](04-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- 投稿の全項目を編集できること
- 編集しても投稿日時（新着順の基準）が更新されないこと
- 投稿者本人以外は編集できない（共同アルバムのオーナーであっても他人の投稿は編集できない）こと
