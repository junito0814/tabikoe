# Task 2: ブロック対象コンテンツ除外の共通フィルタ実装

> 出典: [blocking.md](../../../user-stories/safety/blocking.md)
> インデックス: [blocking](00-index.md)

## 依存

- [Task 1: ブロック／解除 Route Handler](01-block-unblock-handler.md)

## 実装内容

- ログインユーザーが「ブロックした」または「ブロックされた」相手のユーザーIDを取得する共通関数（例：`getBlockedUserIds(userId)`）をRoute Handlers内に実装する
- 投稿一覧・地図のピン・コメント・プロフィール・アルバム一覧等、ユーザーが紐づくコンテンツを取得するクエリにこの関数を組み込めるよう、除外条件（`user_id NOT IN (...)`相当）を返すインターフェースとして提供する
- 例外ルール：アルバム（`trips`）内の投稿一覧を取得する場合は、この除外フィルタを適用しない（アルバムメンバー間ではブロック関係があっても相手の投稿を表示する。3.8.2準拠）。呼び出し側が「アルバム文脈かどうか」を引数で指定できるようにする

## 成果物

- `getBlockedUserIds`等の共通フィルタ関数（ブロック除外ヘルパー）
- 利用ガイド（どのクエリにどう組み込むかを、他ストーリーの実装者が参照できる形でコメント・ドキュメント化する）

## テスト要件

### 単体テスト
- 双方向（自分がブロックした相手／自分をブロックした相手）のユーザーIDが正しく取得されることを検証する
- アルバム文脈フラグを指定した場合、除外リストが適用されない（空として扱われる、または呼び出し側でスキップされる）ことを検証する

### 結合テスト
- テスト用DBで、ブロック関係にある2ユーザー間で、通常の投稿一覧取得時に互いの投稿が除外されることを確認する
- 同じ2ユーザーが同一アルバムのメンバーである場合、アルバム内投稿一覧では互いの投稿が除外されないことを確認する

### E2Eテスト
- なし（[Task 4: 受入テスト（E2E）](04-acceptance-e2e.md)でまとめて検証する。ただし本タスクの効果は、消費側の各機能ストーリー（map-search・browsing・records等）が本フィルタを組み込んだ時点で画面上に反映される）

## 関連する受入条件

- ユーザーをブロックすると、そのユーザーの投稿・コメント・プロフィール・アルバムが相互に表示されなくなること
- 共同アルバムのメンバー同士がブロック関係にある場合でも、アルバム内では相手の投稿が表示されること
