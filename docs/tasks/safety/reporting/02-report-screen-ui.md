# Task 2: 通報画面UI（SC-11、対象別の理由選択肢出し分け）

> 出典: [reporting.md](../../../user-stories/safety/reporting.md)
> インデックス: [reporting](00-index.md)

## 依存

- [Task 1: reports テーブルのスキーマ定義・マイグレーション](01-reports-schema-migration.md)

## 実装内容

- 通報画面（SC-11）を実装する。投稿詳細・コメント・ユーザープロフィール・スポット・アルバムの各画面から、対象を特定した状態で本画面に遷移できる導線を設ける
- 通報対象（`target_type`）に応じて、理由選択肢の表示を出し分ける
  - 共通：不適切な表現／個人情報の掲載／虚偽の情報／著作権・肖像権の侵害／スパム・宣伝目的／その他
  - `target_type='user'`の場合のみ「なりすまし」を追加表示
  - `target_type='spot'`の場合のみ「スポット情報の誤り」を追加表示
- 自由記述欄（任意、1,000文字まで、書記素クラスタ単位でカウント）を設ける
- 送信前に、対象への重複通報がある場合はサーバー応答（Task 3のRoute Handlerが返すエラー）をもとにエラーメッセージを表示する

## 成果物

- SC-11通報画面コンポーネント
- 各画面からの通報導線（投稿詳細・コメント・プロフィール・スポット・アルバム）

## テスト要件

### 単体テスト
- `target_type`ごとに表示される理由選択肢が仕様どおりであることを検証する（`user`のみ「なりすまし」、`spot`のみ「スポット情報の誤り」が表示される）
- 自由記述欄が1,000文字（書記素クラスタ単位）を超えると送信ボタンが無効化される、またはエラー表示されることを検証する

### 結合テスト
- 各画面（投稿詳細・コメント・プロフィール・スポット・アルバム）からSC-11に遷移した際、正しい`target_type`・`target_id`が引き継がれることを確認する

### E2Eテスト
- なし（[Task 5: 受入テスト（E2E）](05-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- 通報画面（SC-11）で、通報対象に応じて通報理由の選択肢が出し分けられること（なりすましはユーザー通報時のみ、スポット情報の誤りはスポット通報時のみ選択可能）（8章 受入条件20）
- 理由選択（必須）と自由記述（任意、1,000文字まで）で通報を送信できること
