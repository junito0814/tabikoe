# Task 5: バッジ新規獲得時のトースト表示

> 出典: [status-badges.md](../../../user-stories/badges/status-badges.md)
> インデックス: [status-badges](00-index.md)

## 依存

- [Task 2: 投稿数・都道府県バッジの判定ロジック（投稿作成時）](02-post-count-prefecture-badge-evaluation.md)
- [Task 3: いいね数バッジの判定ロジック（いいね受領時）](03-like-count-badge-evaluation.md)

## 実装内容

- Task2・3が返す「新たに獲得したバッジの一覧」を受け取り、投稿作成完了時・いいね受領時（本人がその場にいる場合、すなわち自分の投稿作成完了時のみ。いいねは他ユーザーの操作で発生するため対象外）にトーストで表示する共通UIコンポーネントを実装する
- 通知一覧（SC-14、3.9参照）には一切記録しない
- 複数バッジを同時獲得した場合は、順番に、または一括でまとめて表示する（表示順は獲得判定順でよい）

## 成果物

- バッジ獲得トーストコンポーネント
- 投稿作成フロー（posts/post-creation）への組み込み

## テスト要件

### 単体テスト
- 新規獲得バッジが0件の場合、トーストが表示されないことを検証する
- 新規獲得バッジが複数件の場合、すべて表示されることを検証する

### 結合テスト
- 投稿作成〜バッジ判定〜トースト表示までの一連の流れを、テスト用DBで確認する

### E2Eテスト
- なし（[Task 6: 受入テスト（E2E）](06-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- バッジを新たに獲得した際、その場でトースト表示され、通知一覧（SC-14）には残らないこと
