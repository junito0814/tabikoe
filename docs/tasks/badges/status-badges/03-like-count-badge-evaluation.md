# Task 3: いいね数バッジの判定ロジック（いいね受領時）

> 出典: [status-badges.md](../../../user-stories/badges/status-badges.md)
> インデックス: [status-badges](00-index.md)

## 依存

- [Task 1: バッジ種別・獲得閾値の定義（共通カタログ）](01-badge-catalog-definition.md)

## 実装内容

- いいね付与処理から呼び出される共通関数として実装する。呼び出し元は本ストーリーの対象外である「いいね」機能（browsing/likesストーリー、本バッチで並行作成中）のRoute Handlerであり、当該ストーリー側でこの関数を組み込む前提とする
- 投稿者（いいねを受けたユーザー）の累計獲得いいね数（自分自身によるいいねを除く。全投稿の合算）を集計し、Task1の閾値配列（1/10/50/100/200）のいずれかに新たに到達した場合、`badges`テーブルへ該当`badge_type`（例：`like_count:50`）をINSERTする
- 呼び出し元（いいね付与処理）に、新たに獲得したバッジの一覧を返す関数シグネチャとする（[Task 5: トースト表示](05-badge-toast-notification.md)で利用）

## 成果物

- いいね数バッジの判定・付与関数（`awardLikeCountBadgeIfEligible(userId, newTotalLikeCount)`相当のインターフェース）
- browsing/likesストーリー向けの組み込みガイド（関数シグネチャ・呼び出しタイミングの説明）

## テスト要件

### 単体テスト
- 累計いいね数が49→50件になるケースで`like_count:50`が付与されることを検証する
- 累計いいね数が50→51件になるケースで新たなバッジが付与されないことを検証する
- 自分自身の投稿への自分のいいね（発生しない前提だが）が集計に含まれないことを検証する

### 結合テスト
- テスト用DBで、複数投稿にまたがる累計いいね数が閾値に到達した際に`badges`テーブルへ正しくレコードが作成されることを確認する。実際の呼び出しはbrowsing/likesストーリーのいいね付与処理経由で検証する

### E2Eテスト
- なし（[Task 6: 受入テスト（E2E）](06-acceptance-e2e.md)でまとめて検証する）

## 関連する受入条件

- いいね数バッジ（1／10／50／100／200件）が、累計獲得いいね数の到達時点で正しく付与されること
