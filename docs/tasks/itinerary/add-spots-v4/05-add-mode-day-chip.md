# Task 5: 追加モードに Day の札を付け、帯から Day を外す

> 出典: [add-spots.md](../../../user-stories/itinerary/add-spots.md)「投稿から探す（追加モード）」「追加モードの表示」「Day の選び方」

## 背景

追加モードは、今は帯に「〈アルバム名〉 Day n に追加中 [完了]」と出し、カードの「＋」を押すと**帯の Day** に入る（旧 [add-spots Task 2](../add-spots/02-add-mode.md)）。Day を変えるには、しおりに戻ってタブを選び直すしかなかった。

2026-11-07 に、**Day はカードの札で選ぶ**ことにした。帯からは Day を外す（決定事項 102）。シート（Task 4）と同じ札・同じ決まりにする。

## 実装内容

### 5-1. 帯

- `AddModeBanner` の文言を「〈アルバム名〉 に追加中 [完了]」にする（Day を外す）。「完了」でしおり詳細に戻るのは今のまま
- URL の `day` は残す。意味は「**札の最初の値**」に変わる（`?itinerary=<id>&day=<n>`）

### 5-2. カードの札

- 追加モードのとき、カード（投稿カード・スポットカード・スポット別一覧の「＋」）の「＋」の左に Day の札（`DayMoveDropdown`）を出す。期間の無いしおりでは出さない
- 最初の値は URL の `day`。変えたあとの決まりは Task 4 の `nextAddDay` をそのまま使う（**決まりの写しを作らない**。AGENTS.md 14）
- 札の値は画面の中で 1 つだけ持ち、カードごとに持たない（決めてほしいこと 11 の答えによる）。無限スクロールで後から出たカードも、その値から始まる
- 札を変えたら URL の `day` も書き換える（`router.replace`。履歴を増やさない）。投稿詳細へ行って戻ったときに、選んだ Day が残るため

### 5-3. 入っている場所

- 入っている場所は、札に**入っている Day** を出し、「＋」を**青い ✓** にする（今は ✓ だけで、色はほかと同じ）。✓ を押すと外れる
- 入っている Day を出すため、`loadAddMode` が返すものを `spotIds: string[]` から **`spot_id` → `day_index`** の対応に替える
- 入っている場所の札を変えると、その場で Day を移す（Task 4 と同じ。`PATCH /api/itineraries/[id]/spots/[spotId]`）

### 5-4. `SaveButton` の追加モード

- 今は `addMode.day`（帯の Day）で入れている。札の値を受け取って入れるように替える
- 札と「＋」を 1 つの部品（`AddModeSaveControl` のような名前）にまとめ、シート（Task 4）の候補の行でも同じものを使う

## テスト要件

### 単体テスト
- 帯に Day が出ないこと（「大阪旅行 に追加中」）
- カードの札の最初の値が URL の `day` であること。札を変えると、ほかのまだ入っていないカードの札も同じ値になること（決めてほしいこと 11 の答えで書き直す）
- 「＋」で札の Day を付けて入れる呼び出しが走ること（帯の Day ではない）
- 入っている場所に入っている Day と青い ✓ が出て、✓ で外れること
- 期間の無いしおりで札が出ないこと
- `loadAddMode` の形を変えても、今の `add-mode.test.ts`（行き先の自動決定）が書き換えずに通ること
